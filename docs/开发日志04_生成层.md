## 一、四段式决策记录

### 决策 F：声明制对账（幻觉防控的核心机制）
- **决策**：模型输出结构化 JSON，必须对每个 cause 声明 `figures`（正文用到的全部数字）与 `citations`（引用的 chunk_id）；代码侧三重校验——① 声明的数字必须在产物包白名单内 ② 正文出现的数字必须全部被声明 ③ 声明的出处必须真实存在于知识包。任一不过 `verification.passed=False`
- **优点**：把"大模型幻觉"从不可控风险变成**可检测、可退回**的工程问题；正向（声明⊆白名单）+反向（正文⊆声明）双向夹击，"声明一套写一套"也逃不掉；校验在代码侧，模型不可见不可绕过
- **缺点**：模型多一层声明负担，能力弱的模型可能声明不全导致误报退回（需重试或人工）；白名单含知识块文本中的数字，模型引用知识块数字（如维修费 8,500）合法但也意味着这些数字不被"精确性"校验（它们本来就不是计算产物）
- **裁决**：值得——这是"大模型永不算数"原则在输出端的 enforcement 层；没有校验的 Prompt 纪律只是倡议

### 决策 G：手写 httpx LLM 客户端，不用 openai SDK
- **决策**：OpenAI 兼容协议就是一次 POST /chat/completions；配置走环境变量（LLM_BASE_URL/LLM_API_KEY/LLM_MODEL），tenacity 三次指数退避
- **优点**：少一层依赖少一类主版本断裂（D1 教训）；Kimi/DeepSeek/Qwen 均兼容该协议，换厂商只改环境变量
- **缺点**：失去 SDK 的类型提示与流式等高级特性（本场景不需要流式）；协议细节（如各家 reasoning 字段）需自行跟进
- **裁决**：值得——竞赛场景只需要同步补全，依赖最小化优先

### 决策 H：MockLLM 离线测试策略
- **决策**：测试断言**解析与校验逻辑**而非模型效果；正例用真实产物包动态构造"优质输出"保证永远自洽，三个负例分别锚定编造数字/漏声明/编造出处
- **优点**：CI 与演示机无 API key 也能全量回归；校验器行为被精确保住
- **缺点**：**真实模型的指令遵循率未经验证**——Prompt 铁律在实际模型上的表现需接入真实 LLM 后观察（如实标注：本轮未配置真实 key，未做实弹调用）
- **裁决**：正确分层——逻辑正确性与模型效果分开验证，前者本轮完成，后者列入联调待办

### 决策 I：检索查询由分析条件+告警自动构造
- **决策**：`build_query` = 产品名 + 月份 + 告警要素 + 量差价差影响前 2 的材料
- **优点**：检索与计算联动（告警什么就查什么），不是写死的关键词；评审能看到"系统知道该查什么"的智能感
- **缺点**：查询质量依赖告警/分解的触发情况，无告警月份查询偏泛（退回产品+月份+成本变动的通用查询）
- **裁决**：值得

## 二、本轮新发现缺陷（已全部修复）

### D17. 日期豁免被负号绕过【已修复】
- 现象：`2026-05` 中"2026"被日期正则豁免，但"-05"被数字正则当作 -5 捕获——豁免失效
- 性质：两个正则各自正确、组合出漏洞（先匹配后豁免的顺序错误）
- 修复：改为**预处理豁免**——先删日期模式再抽数字；`test_number_extraction_exempts_dates` 锚定

### D18. 页码引用被当作未声明数字【已修复】
- 现象：正文"见《配方文档》p1"的页码 1 被抽出，误判"未在 figures 中声明"——正例测试失败
- 修复：预处理同时豁免 `p\d+` 页码引用格式
- 教训：校验器的"数字"定义必须枚举清楚豁免域（日期/页码），边界进测试
