## D1 F3 告警行动卡片列（替换只读横幅）

- **决策**：新增 `AlertActionCards.vue`——每条告警一张卡：红色左边条 + 通道标签 +
  方向徽章（涨红/跌绿）+ 消息 + 三动作按钮。**确认**=会话级消单（卡片变暗可撤销）；
  **生成归因**=复用既有 generate() 并平滑滚动到归因面板；**下发整改**=POST
  /api/rectify/dispatch，结果行如实呈现（task_id/责任人/截止/微信推送状态；
  RPA 不可达显示 dispatch_failed 与恢复路径，不粉饰）。
- **关键认知**：后端 dispatch 是**月级幂等装配**（按任务标题去重），前端按"任务标题含
  告警要素名"匹配本卡任务（纯函数 `matchTask`，不构造任务）；重复下发返回
  note"幂等跳过"原样展示。
- **优点**：告警从"看了"变"处置了"——赛题模块四（告警→整改→推送）在 UI 层闭环；
  确认态会话级是刻意的：告警确认不该静默永久消失（刷新即恢复待处置）。
- **缺点**：确认不落库——刷新后恢复（评委演示无碍；企业化需后端 ack 接口，列入
  演进清单）；月级下发意味着两张告警卡分别点"下发"时第二张必得"幂等跳过"——
  语义正确但需用户理解，靠结果行文案解释。
- **验证**：DOM 实测卡片渲染、三按钮齐备；matchTask/alertKey/momTone 单测 4 项。

## D2 F4 主从布局 + 容器查询降级

- **决策**：趋势主图 1.6fr 加高（tall，min-height 420）、右侧列堆结构+瀑布
  （min-height 220 小图）、热力图全宽沉底；降级用 **CSS 容器查询**
  （`.content` 设 `container-type: inline-size`，`@container (max-width:600px)` 单列）。
- **为什么不用媒体查询**（实测踩坑）：媒体查询只看视口——用户 742px 面板下，
  侧栏展开（内容区 479px）与收起（619px）得到的是同一个答案，主从布局要么
  永不出现要么硬塞。容器查询感知侧栏状态：展开→自动单列保可读，收起→自动
  恢复主从。"收起侧栏进入分析视图"成为自然交互叙事。
- **次生缺陷与修复**：ECharts 初始化后容器带内联像素宽，grid 项默认
  `min-width:auto` 被顶爆（趋势列被挤到 49px）——所有 grid 项显式 `min-width:0`。
- **优点**：布局随内容区宽度连续适应，无需 JS 监听；宽屏（评委全屏）下主从
  信息密度最高。
- **缺点**：侧列 233px 是紧凑态——瀑布图靠"轴标签短化（上月(2026-04)→上月，
  全名留 tooltip）+ 标签 10px + 旋转 28°"保住可读，柱顶数值仍略挨；
  容器查询需 Chrome 105+（评审环境现代浏览器，可接受）。
- **验证**：DOM 实测两态切换（侧栏展开 479px 单列 ↔ 收起 619px 主从 372/233）。

## D3 图表联动（V4）

- **决策**：① 告警 pin——当前月有告警时趋势图单位成本主线钉红色 pin
  （数量=告警条数，`trendOption` 第三参，纯函数）；② 选中描边——热力图当前
  产品×月份格子加深色描边（per-item itemStyle，`heatmapOption` 第二参）；
  ③ 点格切换——ChartPanel 透传 ECharts click，行名"产品·要素"解析产品 +
  列取月份写回 store，watcher 自动全面刷新。
- **优点**：三个动作全部走"纯函数 option 变换 + store 单一状态源"，零命令式
  图表 API 调用，可单测；描边/pin 的坐标全部由后端数据索引摆放，不涉计算。
- **缺点**：点格后整页刷新（重取 6 个接口）——闪烁感存在但 <1s；首月环比为
  null 的格子点击也会切换（语义上无数据月份仍可选，与筛选器行为一致）。
- **验证**：linkage.test.ts 7 项（pin 坐标/无 pin 分支、描边数量与位置、
  无参原样、matchTask/momTone）；截图实测描边可见、点格提示在标题旁。

## D4 结构图窄态重叠修复（用户反馈"字体与图框重叠"，2026-09-21 早）

- **根因**（三处叠加）：内环饼心仅 ~36px 半径却要塞"名称+数值"三行标签；
  外环"名称 数值"标签过宽互撞；普通图例在窄列下换 5 行吃掉半个图表区。
- **决策**：内环标签只放数值（`{c}`，名称由图例+悬浮框承担——颜色→名称映射
  图例已有，信息不丢）；外环标签只放名称并截断 72px（全名与数值留悬浮框）；
  图例改 `type:'scroll'` 单行翻页，不再挤压饼图空间。
- **优点**：窄列下饼图区增高约 40px、标签碰撞面从三处降到零；宽屏下滚动图例
  单行显示同样更整齐。信息总量无损（全部细节在悬浮框）。
- **缺点**：轴上即读性下降——不看悬浮框时内环只见数值不见名（靠图例反查，
  三要素颜色已跨图训练过用户，成本可接受）；长物料名截断带省略号
  （"包装材料(盒+…"），悬浮框补全。
- **验证**：vitest 28 项全绿、build 通过；画布内部无法 DOM 断言，
  已由用户目检确认（浏览器标签页隐藏时截图不可用，修复基于已知几何推导）。
