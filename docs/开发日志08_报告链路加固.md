## 二、三处加固（四段式记录）

### 2.1 find_soffice 优先 soffice.com

- **决策**：Windows 上优先返回 `soffice.com`（控制台宿主包装）而非 `soffice.exe`（GUI 子系统）
- **优点**：`soffice.com` 不脱离父进程控制台——stdout/stderr 不丢、exit code 可信、
  `subprocess.run(timeout=...)` 的等待语义成立。实测证据：对 `soffice.exe --version`
  调用挂起 60 秒直至超时（GUI 进程脱离控制台后主进程即刻退出、实际转换进程游离）；
  `--headless --version` 退出码 0 但零输出（GUI 程序 stdout 无法回传）
- **缺点**：依赖 LibreOffice 发行版自带 `soffice.com`——个别精简打包版可能只有 exe；
  兜底逻辑保留（com 找不到退回 exe，exe 不可用再降级 warnings）
- **裁决**：选定——挂起 60 秒的实证说明 exe 路线在自动化场景下不可用，
  com 是 Windows 平台 headless 转换的事实标准入口

### 2.2 隔离 UserInstallation profile

- **决策**：每次转换传 `-env:UserInstallation={tempfile.mkdtemp().as_uri()}` + `--norestore`
- **优点**：根治两类稳定性杀手——①首次启动创建用户 profile 时的初始化挂起
  （与 2.1 的 60 秒挂起同源）；②多报告连续/并发转换时共享 profile 互踩
  （LibreOffice 单实例锁，第二个进程会转去和第一个进程通信而非自己干活）。
  tempfile 隔离 = 每次转换都是"干净首启"，状态不可污染
- **缺点**：每次转换多一次 profile 初始化开销（实测每次转换约 3~6 秒，
  三报告串行总耗时 ~15 秒，可接受）；临时目录不主动清理（依赖 OS temp 策略，
  单次仅 KB 级）
- **裁决**：选定——报告生成是低频操作，几秒开销换"并发互踩"这类玄学故障的根治，值

### 2.3 动态表样式：手工 XML 边框 + 表头底纹

- **决策**：弃用 try/except `Table Grid` 样式方案（**模板里根本没有这个命名样式**——
  这就是日志07 空壳表 bug 的根因链条），改为 `_apply_table_style(table)` 手工写 XML：
  六边边框 single/sz=4/000000（含 insideH/insideV）+ 表头行 D9D9D9 底纹加粗。
  参数全部从官方模板自带表格的 tblBorders 实测提取
- **优点**：动态插入的 6 张表与模板自带 9 张表视觉完全一致（边框/表头底纹），
  评审肉眼无差；不再依赖任何命名样式的存在性，样式来源从"运气"变成"代码"
- **缺点**：样式参数硬编码（border sz=4、底纹色 D9D9D9）与模板当前版本耦合——
  模板改版配色时需同步改代码；粒度只到"表头行"，不做斑马纹等更复杂样式
- **裁决**：选定——耦合面与注册表同级（已有漂移测试文化兜底），
  且"模板自带表什么样、动态表就什么样"正是赛题模板保真要求的延伸
