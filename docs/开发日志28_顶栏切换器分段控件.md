# 开发日志 28 · 顶栏切换器 redesign（选型方案三落地）

## 背景

用户实测反馈：顶栏的产品/月份切换器只是两张无标签白卡（原生 select），
"切换地方用户不能明确知道在哪里"。第一版选型页视觉不达标被驳回，
第二版精修（品牌紫梯度/分层投影/悬浮态画出）后用户选定**方案三：分段控件 + 月份步进器**。

## 决策

1. **产品选择**：原生 select → 分段控件（segmented control），三个产品全平铺，
   当前项浮起白卡旋钮（`aria-pressed` 保留语义）。无下拉隐藏，可发现性满分。
2. **月份选择**：`‹ 2026-02 ›` 步进器——相邻月一键（分析师按月巡检的主动线）；
   中间月份值保留原生 `<select>`（appearance:none 隐形），点按仍可全月直跳，
   长跨度跳转不退化。端点钳制：首月锁 ‹、末月锁 ›（`canStep` 驱动禁用态）。
3. **数据截至**：从灰色小字升级为带绿点的徽章式标注（条款 4 时间戳必标，不降级）。
4. **纯函数抽出**：`stepper.ts`（stepMonth/canStep），端点钳制与异常输入有 vitest 锁定。

## 优点

- 可发现性根治：所有产品选项摊在眼前，选中态一目了然，零弹出层
- 交互成本最低：相邻月一键，产品一键；实现最简单（纯按钮，无自绘 Popover 的稳定性风险）
- 与热力图"点击格子联动切换"形成互补：格子=跨产品跳转，段选=同页平铺切换
- 原生 select 保留在月份值上：键盘可达性、跨月直跳、表单语义全部不丢

## 缺点

- 横向占位最大：三产品段选 + 步进器约 520px，窄屏依赖 flex-wrap 折行（已处理）
- 产品数硬上限约 4 个——本项目赛题固定 3 个产品，够用；若企业演进期产品变多需改回下拉
- 月份步进跨 6 个月以上要连点（月份值点按下拉兜底，可接受）

## 验证

- vitest **80 全绿**（新增 `stepper.test.ts` 4 项：步进/端点钳制/异常输入/禁用态）
- `vite build` 干净；web 容器重建后 200
- 浏览器 DOM 实测：段选三产品渲染、选中态正确；点"下一月"月份 2026-05→2026-06
  且末月时"下一月"自动禁用；点"六味地黄胶囊"选中态切换正确
