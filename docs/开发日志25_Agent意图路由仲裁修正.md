# 开发日志 25 · Agent 意图路由仲裁修正（rule-arb）

日期：2026-09-22

## 决策

用户实测发现：聊天抽屉里只说关键词（如"报告""对标"）无法触发执行，必须说完整指令句。
实弹复现定位根因（`repro_chat.py`，8 组输入）：

- `报告` / `对标` 单词 → LLM 分类给了正确意图但置信度 **0.6 < 阈值 0.7** → 旧代码直接四入口，
  且**禁止规则层出场**（旧注释："不让规则层凌驾于模型的'我没把握'之上"）；
- 而分类器系统提示里写着"拿不准……confidence 给低分"——DeepSeek 忠实执行了这条，
  对单关键词一律压到 0.6。**提示词自伤 + 规则层被锁死**叠加，模型的"谦虚"否决了确定性证据。

修复（方案 A：仲裁修正，对比了 B 提示词修正 / C 降阈值，见下）：LLM 低置信时放规则层仲裁——
用户文本含确定性关键词即执行，`layer` 如实标注 `rule-arb`；双不命中才四入口；域围栏不动
（LLM 显式判 `none` 仍直接拒答，规则层不得捞回，`test_out_of_scope_not_rescued_by_rules` 守住）。

三方案对比：

| 方案 | 优点 | 缺点 | 裁决 |
|---|---|---|---|
| A 仲裁修正 | 确定性证据优先；行为可测试不漂移；域围栏不动 | 存在 LLM 低置信说 A、规则命中 B 的理论冲突——取用户亲自打出的关键词（硬证据） | ✅ 采用 |
| B 提示词修正（"含明确关键词给高分"） | 不改架构 | 置信度是模型自评数字，不可测试、会漂移（实弹中"看板"两次调用分别得 0.9 与低分，证实漂移） | ❌ |
| C 降阈值 0.7→0.55 | 一行改动 | 全局安全闸削弱，真正含糊的输入也会蒙混过关 | ❌ |

## 优点

- 单关键词输入（"报告"/"对标"/"看板"）全部直通执行，用户不再需要背指令句式；
- 防幻觉纪律实质未削弱：无关键词硬证据的含糊输入（"帮我看看那个情况"）仍四入口，
  域外请求仍显式拒答——"不猜"原则从"模型说没把握就不动"修正为"没有硬证据才不动"；
- `layer=rule-arb` 如实披露仲裁行为，可观测性不丢；
- 顺带对冲了 LLM 置信度漂移：模型自评数字不再能单方面否决确定性匹配。

## 缺点

- 理论上存在"LLM 低置信判 A、关键词命中 B"的分歧情形，此时执行 B——
  若模型低置信判断其实是对的，会执行错意图（但用户文本里确实打着 B 的关键词，
  错也在用户输入本身，且抽屉里可继续纠正）；
- 规则层权重整体上升，关键词表的维护责任变重（表外新说法仍靠 LLM 主线兜住）；
- 旧测试 `test_low_confidence_not_overridden_by_rules` 的前提被推翻并删除——
  这是设计哲学的显性转向，已用三个新测试重新钉死边界。

## 验证

- pytest **172 全绿**（新增：低置信仲裁执行 / 低置信分歧硬证据优先 / 无关键词仍四入口；
  修复过程中抓到自身一个 bug：先覆盖 conf 再判断 `conf==0.0` 导致 LLM 破损场景误标
  rule-arb，已调整赋值顺序并回归）；
- 实弹复测 8/8 直通：`报告`→report·rule-arb、`对标`→benchmark·rule-arb 等，见 repro 输出；
- 浏览器实测：抽屉输入"报告"→ 直接生成 Word+PDF，卡片标注"意图 report · 置信 0.9 · rule-arb"；
  胡言乱语（"想熏了"）仍正确弹四入口。
