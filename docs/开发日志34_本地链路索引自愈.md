# 开发日志 34 · 本地链路索引自愈（2026-09-24）

## 背景

队友在另一台电脑裸克隆仓库实测发现严重问题：本地开发启动后知识库功能报"索引未构建"，
而仓库没有任何构建入口与说明——`python -m app.kb` 因无 `__main__` 守护而静默无输出。

## 根因（三连坑）

1. `app/kb.py` 只有 `build_index()` 函数，无标准命令行入口；
2. Docker 链路有 entrypoint 自动建索引，**本地开发链路行为不一致**——裸奔报错；
3. README 本地开发段未提索引构建，也没说语料来自 COST_INSIGHT_DATA_DIR。

设计教训：**两条启动链路（Docker/本地）必须行为对齐**——Docker 有的自愈，本地也必须有。

## 修复（三层）

| 层 | 改动 | 作用 |
|---|---|---|
| 自愈（治本） | `api._init()` 调用新增的 `kb.ensure_index()`：索引缺失且语料在场则现场构建；语料缺失给中文指引（指向 README 第 0 步） | 队友无需知道这一步存在 |
| 入口（治标） | `app/kb.py` 加 `main()` + `__main__` 守护，`python -m app.kb` 可用且幂等（已存在则提示无需重建） | 手动重建有标准命令 |
| 文档（兜底） | README 本地开发段补"索引首次启动自动构建 + 手动命令" | 三层保险 |

## 优缺点

- 优点：本地/Docker 行为对齐；裸克隆零知识成本启动；语料缺失的报错是人话。
- 缺点：首次启动多约 30 秒建索引（仅一次，有日志明示）；`_init()` 职责变重（启动编排本就该管就绪）。

## 验证（模拟裸克隆实测）

1. 挪走 `data/kb/` → `python -m app.kb` → 现场构建 351 块，日志清晰；
2. 再跑一次 → 幂等提示"已存在，无需重建"；
3. 删除索引 → 直接调 `api._init()` → 自动构建 + `products` 接口出数；
4. 全量 pytest 180 项全绿。
