## D30 知识图谱增强检索（加分项 3.10，kg.py 桩 → 最小自研）

- **决策**：LightRAG 思路最小自研——纯规则实体抽取（"字段: 值"记录模式+文件名产品词表）
  → 三类边（contains/made_by/cooccur）→ 图扩展召回作为 RRF 第三通道 "graph"。
  **零新依赖**：邻接表 dict-of-set 自实现，弃 networkx（评估文档原建议，实际未装也不必装）。
- **优点**：确定性可复现、毫秒级建图、无 LLM 抽取成本；`kg.json` 随索引持久化，
  检索侧缺文件现场重建自愈；跨文档关联查询（"金银花涨价影响哪个产品"）能把
  产品配方簇拉进候选——这是向量/BM25 做不到的。
- **缺点**：规则抽取依赖"表格感知抽取留下字段:值记录"这一前置约定，换数据源格式
  要补模式；实体词表由文档驱动，未在文档出现的实体不入图（行情 CSV 的"山茱萸"
  仅在配方变更块提及才进图）。
- **验证**：11 项测试（实体/边/提及/扩展召回/持久化往返/RRF 三通道），全绿。

## D32 两个薄端点（3.9 知识库热更新 / C3 对标透出）

- **决策**：`/api/benchmark/{product}/{month}` 直接透出双向口径 DiffTree；
  `/api/kb/documents` GET/POST/DELETE + BackgroundTasks 旁路重建索引 +
  检索器单例热切换。**上传用 JSON+base64 而非 multipart**——托管运行时无
  python-multipart，不新增依赖。
- **优点**：底层函数全现成，端点只做编排；重建失败不影响在线服务（旧索引
  继续服务）；KB_DIR 路径穿越防护（只取文件名）。
- **缺点**：base64 体积 +33%，大文件不友好（竞赛文档 <5MB 可接受；企业演进
  换 multipart，路由签名不变）；重建是全量重嵌入而非增量（百级块秒级可接受，
  万级块需换 Langchain-Chatchat 式增量队列）。

## D33 容器化（C5 硬约束：两容器而非三容器）

- **决策**：`app`（python:3.12-slim + LibreOffice 层照 gotenberg 安装写法 +
  自带字体 fc-cache + 烘焙模型强制离线）+ `web`（node 多阶段构建 → nginx 反代）。
  **弃三容器**（renderer 独立）：render.py 本机 subprocess 调 soffice，
  同容器零代码改动、少一个跨容器故障面。compose 挂考题数据只读卷 +
  COST_INSIGHT_DATA_DIR/VECTOR_BACKEND 环境覆盖（config.py 新增，与既有
  PLACEHOLDER_MAP_PATH/REPORT_TEMPLATE 覆盖同模式）；entrypoint 幂等构建
  Milvus Lite 库。
- **优点**：`find_soffice` 首候选 `shutil.which("soffice")` 在 Linux 容器天然命中，
  渲染链路零改动；模型烘焙入镜像（90.8MB）+ HF_HUB_OFFLINE=1，启动零下载。
- **缺点**：app 镜像体积 +约 600MB（LibreOffice 层），横向扩缩 API 副本时渲染
  能力随之复制（浪费）；**本机无 Docker，实机构建未验证**——compose YAML 语法、
  配置覆盖、COPY 路径均已静态核对，运行时验证留待部署机（验证脚本
  scripts/verify_milvus_lite.py 已备）。

## D34 规则精排（对比评估#3，cross-encoder 的诚实降级）

- **决策**：首选 fastembed cross-encoder（bge-reranker-base），本机离线下载失败
  （HF 不可达）→ 规则精排：RRF 前 10 名窗口内按 IDF 加权词元覆盖率 +
  图谱实体命中重排，只重排不扩召回（错误代价封顶）。
- **优点**：零新依赖零模型体积，确定性可解释；负 IDF 截断防超高频词反噬。
- **缺点（实测结论，不粉饰）**：6 事件基准 MRR 0.778→0.778、Top1 4/6→4/6
  **持平**。诊断：GMP 文档 271 块稀释语料抬高产品名 IDF，判别词优势被压缩；
  RRF 头部差距（47%）超出 coverage 乘性加成可翻盘区间。精排的真实价值是
  近分局平局打破与防御层，测试硬约束"只许赢不许输"（mrr_on ≥ mrr_off）。
  企业演进换神经精排时接口不变（rerank_hits 签名即契约）。
