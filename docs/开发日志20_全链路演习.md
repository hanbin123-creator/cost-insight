## 演习发现的两个真实问题（如实记录）

### 发现 1：本地幂等 × mock 内存态 的状态错位
- **现象**：银黄口服液·2026-05 的任务在上次会话已下发并落库（cost.db）；RPA mock 重启后内存清空，但我方幂等判定"已发送"跳过 → mock 侧永远查不到这批任务，追踪页显示 0。
- **影响**：演示现场若 mock 重启，会出现"我方说发了、对方说没有"的错位。
- **缓解方案（未实施，列入待办）**：演示前脚本一键重置两边（清 cost.db 下发记录 + 重启 mock）；或幂等键加 mock 会话指纹。竞赛演示当前由"标准下发流程一次走完"规避。

### 发现 2：精确编号/代号查询检索薄弱
- **现象**：演习文档含两次编号"ZQ-TEST-2026"，但 `q=ZQ-TEST-2026` 的 Top5 全部落在旧文档（向量通道对无语义编号给出噪声近邻，BM25 通道被全库高频词"2026"稀释）；而语义查询"绿原酸 低温萃取 工时"Top1 精确命中新文档。
- **定性**：混合检索对**自然语言问句强、对精确标识符弱**——RAG 经典短板，赛题问答场景（自然语言成本问题）影响低。
- **优化方案（未实施，列入待办）**：加"精确包含"第四通道（`token in chunk.text` 直接命中加权），或查询侧检测全大写/连字符 token 走精确匹配；代价是多一路召回的 RRF 权重调参。

### 顺带记录：auto_fixed 校验
- 专题报告校验结论为 `auto_fixed`（校验器自动修正了 LLM 产出的某处数字/引用）——双闸校验按设计工作，不是失败；报告正文与校验留痕可在 docx 中复核。

## 排障记录

- evaluate 工具 15 秒上限：长轮询循环会**驻留页面内继续执行**，后续 evaluate 排队超时——教训：页面内轮询每次 ≤10s，等待交给 Bash sleep 分段。
- Git Bash 的 `/tmp` 与 Windows Python 的临时目录不互通——测试文件改为单脚本内联字符串。
- curl 在 Git Bash 下直传中文 URL 会乱码（`无数据: 中药一厂/…`），中文路径查询改用 Python urllib + quote。
