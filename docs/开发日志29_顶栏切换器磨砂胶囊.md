# 开发日志 29 · 顶栏切换器改磨砂一体胶囊（方案五，替代方案三）

## 背景

日志 28 落地的方案三（分段控件）被用户追问"药品多了怎么办"——段选的产品数硬上限
约 4 个。讨论自适应降级（≤4 平铺 / >4 搜索下拉）后，用户裁决：**直接用方案五**
（磨砂一体胶囊），一步到位覆盖现在与未来。

## 决策

1. **形态**：产品 | 月份合进同一枚磨砂胶囊（紫描边 + 大柔影 + 细分隔线 + 图标凹槽），
   "数据截至"升级为蓝色徽章。方案三的分段控件/步进器整体移除，`stepper.ts` 及其测试删除
   （不留死代码）。
2. **实现手法**：每段内嵌**隐形原生 select 覆盖点击区**（`.ghost`，opacity:0）——
   外观 100% 定制，下拉行为/键盘可达性/移动端适配全部保持原生。
   这是不自绘 Popover 的关键取舍：稳定性优先于视觉效果极致。
3. **产品数膨胀的答案**：原生下拉天然兼容任意数量选项——"药品多了怎么办"
   不再需要自适应分支，一层壳解决。

## 优点

- 醒目与克制平衡：描边+柔影聚焦但不抢戏，与白卡体系兼容
- 一体双段表达"产品×月份是同一个查询条件"，语义准确
- 原生行为全保留：键盘可达、移动端系统选择器、任意选项数，零自绘弹出层风险
- 代码量比方案三更小（删了步进器逻辑与禁用态计算）

## 缺点

- 相邻月切换从"一键步进"退回"两下点按"（开列表+选月）——巡检动线略变长
- 无文字标签，首次可发现性弱于方案四（图标凹槽+ caret 已尽量暗示）
- 隐形 select 覆盖是 hack 手法：若未来要加"搜索式下拉"，仍需自绘 Popover 重写

## 验证

- vitest **76 全绿**（stepper 4 项随模块一并移除）
- `vite build` 干净；web 容器重建后 200
- 浏览器 DOM 实测：胶囊双段渲染（银黄口服液 | 2026-05），隐形 select 携带
  3 产品 / 6 月份完整选项；模拟改值后胶囊显示同步切换；徽章"数据截至 2026-06"正常
