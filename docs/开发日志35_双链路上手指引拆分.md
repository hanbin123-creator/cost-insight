# 开发日志 35 · 双链路上手指引拆分

## 决策

README 从"一份文档对所有人说话"拆为**一个分流页 + 两份专引**：

- `README.md`：只留第 0 步（clone+cd）、按身份分流的两条链路摘要、共用说明（数据包 /
  .env / 模板）、CI 徽章说明；详细步骤全部移出
- `docs/快速上手_Docker链路.md`（评委/演示）：前置检查 → clone+cd → 数据包摆放（含目录树图示）
  → 一条命令 → 四象限成功标准 → 可选 LLM → 无数据包预览 → 停止清理 → 撞坑速查表
- `docs/快速上手_本地开发链路.md`（队友/二开）：前置检查（Python 3.11+ / Node 20+）→ clone+cd
  → 数据包 → 后端（索引自愈日志样例原文收录）→ 前端另开终端 → 可选 mock RPA → 成功标准
  → 撞坑速查表（**逐字收录队友实测三连坑**：`Could not open requirements file` /
  `No module named uvicorn` / `系统找不到指定的路径`）→ 测试命令

编写硬规矩：每条命令可直接复制；每步给出"看到什么才算对"的预期输出；坑按
"报错原文 → 原因一句话 → 解法一条命令"三段式，报错原文逐字收录供 Ctrl+F。

## 优点

- 每个读者只看到自己需要的步骤：评委不再被迫读 pip/npm，队友不再被 compose 参数干扰
- README 从 97 行降到约 90 行且信息密度更高，评委第一眼 30 秒内能定位自己的路
- 报错原文进表格后，队友撞坑时搜关键词即可自助解决，不必再来问
- 两专引骨架同构（前置检查→四步→成功标准→速查表），后续维护可对照修改

## 缺点

- 文档从 1 份变 3 份，启动流程变更需同步两处（缓解：README 只留摘要命令，细节单一出处
  在专引；两专引末尾互挂链接）
- 速查表依赖人工收录新坑，覆盖不全的尾巴仍在（缓解：表格结构让补坑成本极低，
  撞一个收一个）

   请将考题数据包放到本仓库同级目录，或设 COST_INSIGHT_DATA_DIR 指向它" ✅
2. **场景 B 设 COST_INSIGHT_DATA_DIR**：现场构建 351 块，日志与专引中收录的样例
   逐字一致 ✅；幂等重跑提示"索引已存在，无需重建" ✅
3. 克隆副本中 `data/` 仅剩 CJKRadicals.txt（部首映射源数据）、`assets/` 仅剩字体，
   确认赛题保密资源无残留 ✅
4. 验证完成后临时目录已清理
