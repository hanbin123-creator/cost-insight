# 开发日志24 · 测试实弹三漏洞修复（V1 .env 加载 / V2 localhost 解析 / V3 人话校验）

> 来源：2026-09-22 测试实弹（23 项）发现的三漏洞，详见
> 《创灵境赛题_测试实弹报告》。本日志记录修复与复验。

## 决策

1. **V1：stdlib 版 .env 加载器**（config.py `_load_dotenv`）——逐行 KEY=VALUE，
   `os.environ.setdefault` 注入；不覆盖已存在环境变量（Docker/评测注入优先），
   无文件静默跳过。零新依赖（python-dotenv 对单文件是多余的）。
   **连带治理**：三个断言"无 LLM 行为"的测试（chat 契约 / report 端点 /
   rectify 端点）原来隐式依赖开发机没配 key，.env 一生效就翻车或打真实 API——
   全部改为显式 `monkeypatch.delenv` 六键，测试 hermetic 化。
2. **V2：RPA 默认地址 `localhost` → `127.0.0.1`**（config.py），
   vite proxy 同步切换。实测本机 Windows 上 Python 对 localhost 每次 HTTP
   调用解析开销 ~2050ms，127.0.0.1 仅 15ms（136 倍差）。
3. **V3：ingest 数值列人话校验**（`_ensure_numeric`，在任何算术之前调用）——
   `pd.to_numeric(errors="coerce")` 找坏格，抛 DataIntegrityError 带
   **文件/列/行/原值**四要素；合法值转 float 写回，下游算术输入更干净。

## 优点

- V1 后 LLM 功能真正活了：报告六段落全部真实生成，归因/意图/润色链路可用；
  且**声明制对账在实弹中真的干活了**（retried=true → verdict=pass）；
- V2 把演示高频动作从"转圈 6 秒"降到 117ms，评委观感质变；
- V3 兑现了手册"坏数据报人话"的承诺，破坏性测试不再露怯；
- 测试 hermetic 化后回归耗时从 56s 降回 29s（不再误打真实 API）。

## 缺点

1. `_load_dotenv` 是手写解析——不支持 `export KEY=` 前缀、行内注释、
   多行值等 dotenv 全语法（当前 .env 只用了最简形态，够用；
   企业版若配置复杂化再换 python-dotenv）；
2. 测试 hermetic 化靠在每个用例里 delenv 六键——新增此类测试时容易忘
   （缓解：失败信息会很明显——意外打真实 API 会慢/翻车，可立刻发现）；
3. `_ensure_numeric` 只覆盖校验/派生用到的数值列，CSV 其他列的坏值
   仍可能在更下游暴露（刻意控制覆盖面，不 speculative 地扫全部列）。

- pytest **170 全绿**（+3 新测：人话报错 / 干净数据过校验 / dotenv 加载器）；
- R6 复测：坏数值列 → `DataIntegrityError: 数据文件 01_成本明细数据/…成本汇总…
  列「直接材料(元/盒)」第 2 行 值「这不是数字」不是数字` ✅；
- N4 复测：dispatch **6220ms → 117ms** ✅；
- A8 复测（真实 DeepSeek）：23s 出 docx+pdf，六段落 sections_source 全 `llm`，
  对账 verdict=pass ✅；
