# 开发日志 27 · 归因报告表格化（排版选型方案一落地）

## 背景

用户实测发现：归因报告"原因 1"把六种材料的价格/用量/价格效应/用量效应全部挤在一整段
散文里（字墙），无法扫读"哪个是哪个、怎么变动的"。先出 5 套排版方案选型页
（`前端选型/归因排版选型.html`，真实数据 mock），用户选定**方案一：表格化归因**。

## 决策

1. **后端结构化透出**：`AttributionReport` 新增 `decomposition: list[Decomposition]` 字段，
   由 `generate_attribution` 在校验后**代码回填**（`report.decomposition = metrics.decomposition`）。
   数字与正文同源同算（compute.py 量价分解），校验闭环天然兼容；`parse_report` 只白名单取字段，
   模型即使在 JSON 里注入伪造 decomposition 也一律丢弃——"大模型永不算数"延伸：分解表模型不可改。
2. **Prompt 规则 9（正文瘦身）**：告知模型"系统会以表格展示逐材料分解明细，正文不必逐材料
   罗列全部数字，点出影响最大的 1~2 种材料即可"——表格管明细，正文讲逻辑。
3. **前端表格块**：`DecompRow` 类型 + `decomp.ts` 纯显示函数（着色/格式化/口径文案）+
   `AttributionPanel.vue` 在总起段与原因列表之间插入"材料量价分解明细"表格。
   着色口径与热力图一致：效应为负（降本）绿、为正（升本）红、零/缺失灰；
   稳价假设行价格/用量显示占位文案，口径列区分"行情价 / 稳价假设·行情未覆盖 / 数据缺失·不分解"。
4. **附带修复（实机发现的存量缺口）**：`web/fixtures/` 只在 vite dev 下可服务，
   生产镜像只拷 `dist/`——演示模式 fixture 在 Docker 部署中会 404（评委无 LLM key
   运行时的兜底路径断掉）。`git mv fixtures public/fixtures`，9 处测试引用同步更新，
   构建后 `dist/fixtures/` 自然入包。

## 优点

- 扫读性问题根治：材料一行一列对齐，谁涨谁跌、价效应还是量效应一目了然
- 分解表数字零幻觉风险：代码回填 + 模型注入丢弃，有测试锁定
- 正文同步瘦身：实测 cause detail 从字墙（六种材料全罗列）缩到只点两名头号贡献材料
- 演示模式（无 LLM 兜底）在 Docker 部署中真正可用——评委无 key 也能看到完整机制演示
- fixtures 单一来源，测试与运行时共用，无漂移

## 缺点

- 规则 9 是"软引导"：模型若仍罗列全部材料数字不算违规（校验照样过），瘦身是趋势不是硬约束
- 表格 6 列在窄视口（左栏 1.4fr）较紧凑，更小屏幕需横向滚动（已加 white-space: nowrap 保底对齐）
- fixtures 迁移改了 9 处测试 import，属一次性成本；`decomposition` 字段在旧 fixture/
  季度场景可缺省（前端按空数组不渲染表格）
