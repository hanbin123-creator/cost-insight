## 决策记录（四段式）

### D1 路由：手写 20 行 hash 路由（src/router.ts），不引 vue-router
- **决策**：`parseHash` 纯函数 + reactive 状态 + hashchange 监听；空/未知 hash 一律回 dashboard。
- **优点**：零新依赖（评审离线环境 `npm install` 不可用时也能装）；与 nginx 静态托管无 history
  fallback 配置冲突（docker 部署不用改 nginx.conf）；20 行全部可单测。
- **缺点**：无嵌套路由/路由守卫——本项目 5 个平级页面用不到。
- **裁决**：值得。企业演进期页面 >10 个再换 vue-router，迁移只需重写 router.ts（视图组件不感知路由实现）。

### D2 全局筛选状态：store.ts 共享产品/月份，而不是每页一套筛选器
- **决策**：顶部筛选条持有 product/month，DashboardView 用 watch 联动刷新；"数据截至"= 月份列表最大值常驻顶栏（条款 4）。
- **优点**：L1→L4 钻取时上下文不丢（从看板跳到对标页，产品/月份保持）；筛选器唯一，心智简单。
- **缺点**：页面级独立筛选（如报告中心按季度选）后续要加局部状态——已在占位页预留。
- **裁决**：值得，钻取连贯性是四级钻取条款的骨架。

### D3 KPI 卡状态不耦合 alerts 数组（浏览器实测抓出的修正）
- **决策**：`unitCostStatus(momPct)` 只看该指标自身环比；告警红由专门的告警卡承担。
- **优点**：ISA-101 纪律严格落地——颜色只标出问题的那个东西；金银花行情告警不再把"单位成本"卡染红。
- **缺点**：KPI 行对"有告警"的整体感知略弱（靠告警卡单点承担）。
- **裁决**：修正成立。第一版 `unitCostStatus(mom, alertCount)` 是过度耦合，实测截图立刻暴露了误导。

### D4 语义色边条默认值是"中性灰"而不是"正常绿/青"
- **决策**：平稳状态的卡片边条为 #d5dde5 中性灰，不上 teal/green。
- **优点**：ISA-101 原文纪律——"运行是默认态，不该吸引眼球"；红色出现时对比度最强。
- **缺点**：界面"活泼度"低，不如全上色好看——这正是用视觉朴素换告警检出速度（<2s 实证）。
- **裁决**：坚持纪律，这是与"大屏花哨风"拉开差距的核心立场。

## D8 侧栏可折叠（用户要求，2026-09-20 晚）

- **决策**：默认展开 200px，底部"收起导航"按钮；收起为 60px 纯图标栏（悬停 title 提示）；
  状态存 localStorage（`ci-sidebar`），下次进入记住选择；宽度 0.2s 过渡。

  折叠时"问 Agent"按钮隐藏（F5 落地后改为图标常驻）。
- **验证**：DOM 级实测——收起/展开两态类名与文字标签切换正确，localStorage 持久化正确
  （隐藏标签页下 getBoundingClientRect 返回 0 是 Chrome 不绘制隐藏页的正常现象，非缺陷）。

## D7 对比度重建（用户反馈"对比太趋同、颜色太淡"，2026-09-20 晚）

- **背景**：D5 把色相收敛到 4 族后矫枉过正——结构图三要素同族蓝绿区分不开、
  单位成本主线不够压阵、瀑布总量柱淡到"没有存在感"。用户要求参考企业工程配色重做。
- **决策**：在收敛纪律内重建区分度，引入 Tableau 10 企业标准分类色做要素层——
  直接材料 #4e79a7 钢蓝 / 直接人工 #76b7b2 青 / 制造费用 #f28e2c 橙，**跨图同色**
  （趋势、结构、瀑布、热力指代同一要素永远是同一色）；单位成本主线加深为 #1f4e79 深海军蓝
  与材料钢蓝拉开明度差；瀑布总量柱改 #54687a 深板岩灰蓝；结构图外环不再灰阶，
  改"族内浅化"（elementTint：蓝族浅蓝、青族浅青、橙族浅橙）；信号红 #c0392b / 绿 #27a06c
  只表达方向、永不进入分类色板；未知物料落 Tableau 尾色（紫/棕/灰）。
- **优点**：三要素 2 秒内可分辨（明度+色相双通道区分，色盲安全）；跨图同色消除了
  "每张图重新建立颜色图例"的认知成本，是企业级 BI（Tableau/Power BI）的标准做法；
  总量柱有了视觉重量，瀑布阅读顺序（总量→增减→总量）成立；全部 token 化，后续页面继承。
- **缺点**：橙色（制造费用）与信号红在小型热力格上相邻时略近——靠明度差（橙亮红深）和
  热力图只染涨跌两色缓解；族内浅化的切片仍需 tooltip 才能读出具体物料名（同 D5 已知缺点，
  是"面积表达占比、颜色表达族"的刻意取舍）。
- **裁决**：值得。收敛≠单色，企业配色的精髓是"有限色板 + 语义稳定映射"，
  D5 管"少"，D7 管"分得清"，两条纪律叠加才完整。
- **测试**：chart-tokens.test.ts 扩至 6 项（主线≠要素色、三要素互异、信号色不在分类板、
  外环 tints 与父级同族、fallback 存在、瀑布三色引用 token）。vitest 18 项全绿。

## D9 组件选型落地：梯形折叠拉手 + Agent 悬浮球（用户点选 A1 变体 + B1，2026-09-20 深夜）

- **背景**：用户在组件选型页（5 套折叠方案 × 5 套 Agent 入口方案）中选定：
  折叠按钮选 A1 但改为"与侧栏融合的外凸梯形拉手"（不要悬浮半圆）；Agent 入口选 B1 右下悬浮球。
- **决策**：
  1. `.collapse-tab`——侧栏右缘外凸梯形拉手：`position:absolute; right:-17px; top:50%`，
     `clip-path: polygon(0 0, 100% 14%, 100% 86%, 0 100%)`，与侧栏同色 var(--nav)，
     视觉上是侧栏"长出来"的把手而非独立悬浮件；hover 变宽 17→20px 并点亮；
     chevron 方向随 collapsed 切换；localStorage 持久化不变（`ci-sidebar`）；窄屏隐藏。
  2. `.agent-fab`——右下角 48px 圆形悬浮球，紫渐变（#3b2f75→#9163cb，导航紫族内渐变），
     星形 SVG 图标；F5 落地前先接轻反馈：点击弹 2.2s toast 预告"Agent 对话面板将在 F5 增量落地"。
  3. 删除原侧栏底部的"问 Agent"按钮与文字折叠按钮（.side-foot/.agent-btn/.collapse-btn）。
- **优点**：梯形拉手与侧栏同色同体，比悬浮半圆少一个"飘在界面上"的视觉元素，
  符合"构件归属于面板"的企业软件直觉（VS Code 活动栏、钉钉侧栏同款思路）；
  clip-path 纯 CSS 实现，零图片零依赖；FAB 把 Agent 从"侧栏一个菜单项"提升为
  "全局常驻助理"（微软 Copilot DAB 范式），且收起侧栏时依然可达——顺带解决了 D8 记录的
  "折叠时 Agent 入口消失"缺点；FAB 渐变用导航紫族内两色，不引入新色相，守住 D5 收敛纪律。
- **缺点**：FAB 是 fixed 定位，窄屏或未来右下角出现其他悬浮件（如回到顶部）时需要
  协调层叠顺序——届时给 fab 预留 z-index 区间即可；梯形拉手宽度 17px，对鼠标精度
  要求略高于原 200px 宽按钮（ hover 加宽 + 整段高度可点缓解）；toast 是过渡方案，
  F5 抽屉落地后删除（一次性文案，不留技术债）。
- **验证**：vitest 21 项全绿（4 个测试文件）；vite build 通过；真后端 + 浏览器 DOM 实测——
  梯形 clip-path 生效、点击后 `sidebar collapsed` 类与 localStorage `collapsed` 正确写读；
  FAB 点击后 toast 出现（MutationObserver 实测 `__toastSeen === true`；
  早前两次查询为 false 是"Vue 下一 tick 渲染 + toast 2.2s 已消失"的时序错觉，非缺陷）。

## D9.1 梯形一体化修订 + 断点修正（用户反馈"不要悬浮，跟侧面合在一起"，2026-09-20 深夜）

- **背景**：D9 的 64px 小梯形挂在侧栏边缘中央，实测观感是"贴上去的小零件"。
  排查中又发现两个连带缺陷：① 评审面板宽 742px（dpr 1.25），恰好命中 ≤760px 媒体查询，
  梯形被 `display:none` 误藏、页面错进手机布局；② 窄布局下 `.sidebar.collapsed` 的 60px
  优先级压过媒体查询的 `width:100%`，侧栏渲染成 60px"紫色树桩"，且模板 `v-if="!collapsed"`
  把文字标签也吞了。
- **决策**（三处联动修改）：
  1. 梯形本体一体化：64→150px 加高、斜边放缓（14%/86% → 8%/92%）、左缘内嵌侧栏 2px
     （right:-15px，任何缩放级别无发丝缝）；去掉 hover 变宽/变色动效，只让箭头增亮——
     读作"侧栏边缘隆起的握把"，不是独立把手。
  2. 断点 760→560px：560–760px 的窄桌面/侧栏面板恢复桌面壳，梯形可见、图表不被过度挤压。
  3. 新增 `effectiveCollapsed = collapsed && !narrow`：真·手机屏（≤560px）忽略持久化的
     收起态，强制展开为带文字标签的横向导航条，根除"树桩"形态。
- **优点**：梯形与侧栏视觉一体（同色、无缝、无浮动感）；742px 评审面板直接可用，
  用户无需手动拉宽窗口；窄屏缺陷从"样式碰运气"改为"状态级保证"（JS 层忽略 collapsed），
  断点数值有了实测依据而非拍脑袋。
- **缺点**：hover 无背景反馈后，可点击性只靠 cursor + 箭头增亮 + title 提示传达，
  首次发现成本略升（可接受——这是低频操作，发现一次即记住）；断点降低后 561–760px
  区间若侧栏展开（200px），内容区剩 361–560px，四张 KPI 卡会换行变两列——
  不报错、不溢出，只是信息密度下降；`narrow` 监听增加约 10 行 JS（可忽略）。
- **验证**：vitest 21 项全绿、build 通过；浏览器实测 742px 面板——桌面壳恢复、
  梯形 display:flex 高 150px 与侧栏同色无缝（截图逐像素确认）、折叠态持久化正确。

## D9.2 弹出式握把（用户要求"变小 + 靠近弹出、离开收回"，2026-09-21 早）

- **决策**：梯形缩小（17×150 → 14×84px），默认完全缩进侧栏内（translateX(-14px) +
  opacity 0，肉眼不可见）；外包一层 28px 宽的边缘热区 `.edge-hotspot`，鼠标进入热区
  梯形滑出（0.18s），离开热区自动收回。
- **关键设计**：热区覆盖滑出/收回两种状态的全部占用范围——若直接用梯形自身的 :hover
  做触发，滑出 14px 后鼠标原地脱悬会立刻收回、收回后又在悬停区，形成闪烁循环；
  父级热区兜住两种几何状态，从结构上消灭闪烁（这正是"自检不如杜绝"原则在 UI 层的应用）。
- **优点**：默认零视觉占用——界面更干净，梯形只在需要时出现；纯 CSS 触发（无 JS 监听器、
  无性能开销）；闪烁问题在结构层根除而非靠延时/防抖补丁。
- **缺点**：完全隐藏意味着零视觉提示，首次发现要靠鼠标游标（热区 cursor:pointer）和
  title 提示——评委演示时由讲解者主动展示，风险可控；热区遮住侧栏右缘 14px×96px 的
  一条纵向区域，该处导航项的右边缘点击被接管（导航项其余 ~186px 仍可点，影响微小）。
- **验证**：vitest 21 项全绿、build 通过；DOM 实测热区存在、梯形默认态
  translateX(-14px)/opacity 0、几何 14×84px、过渡属性齐备（hover 为纯 CSS 触发，
  静态检查即可确认接线正确）。
