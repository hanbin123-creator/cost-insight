# 开发日志 38 · 扩展模糊语义评估（130 条）

日期：2026-11-13

## 背景与测试纪律

原 26 条模糊语义评估曾参与 prompt 修正，继续用它证明泛化能力会有“测试集泄漏”
风险。本次保留原 26 条不动，新增 **104 条从未参与调参的留出用例**，合计 **130 条**。
测试期间未修改 `app/agent.py`、分类 prompt、路由阈值或参数抽取逻辑。

新增覆盖：看板/对标/报告/整改/问答的自然口语变体、页面跳转、页内锚点、
知识库文档自然名称定位、当前页指代、域外对抗、nav 与场景意图边界。
扩展题增加 `expect_params`：除意图与行为外，还逐项核对 view/anchor/product/month，
防止“意图是 nav 就算对”掩盖跳错页面或锚点的问题。

复核口径说明：初跑后按既有“不猜”原则收紧两条指代题——“打开这张图”必须给
内容 chips；“把那个红的打开”在告警卡与热力图均可能为红色时也必须澄清。
其中后者撤回了初拟的 heatmap 唯一答案，避免测试集自身强行猜测。原始输出未改，
下列终版数字按该一致口径重算。

## 失败归因

### 1. 两模型共同失败 9 条：优先修平台，不靠换模型

- **看板与问答/报告边界**：27、32。涉及当前业务数字的问题应进入数据看板链路，
  不能落到只读知识库的 qa。
- **月份规则缺陷**：40。“上一月”被当成“一月”，得到 2026-01 而非上月 2026-05；
  这是确定性解析错误，与模型能力无关。
- **跳转动词缺口**：79。“跳到报告中心”不在 `_NAV_VERBS`，只能给澄清。
- **锚点关键词缺口**：94。“对标差异明细表”未命中“差异表/口径明细”等短关键词，
  只到页面、未到锚点。
- **知识库自然名称匹配过严/优先级错误**：102、103、105、106。要求两个 token
  才命中导致短标题无法定位；“打开整改经验记录”还被页名“整改”抢先路由到整改页。

### 2. 仅小模型失败 14 条：小模型泛化与“不猜”纪律需加强

- 28、36：看板诉求误判为报告。
- 31：超支苗头误判为报告。
- 34、35：当前成本/告警问题误判为知识库问答。
- 29、60、63、66、76：明确域内请求被误拒为域外。
- 80：“切换到知识库”误判为问答。
- 125：“看看整改任务”没有跳转动词，却误判为 nav。
- **107：无目标的“打开这张图”擅自选择结构图。**
- **108：有歧义的“那个红的”擅自选择告警卡。**

### 3. 仅 DeepSeek 失败 2 条

- 69：“银黄口服液的配方都有啥”误拒为域外。
- 126：“瞅瞅对标分析”无跳转动词却误判 nav。

这说明扩展题不是“专为难小模型”：主模型也存在独立失误，评估集对两者同口径。

## 优先级与后续边界

- **P0：不猜纪律**（107、108）与错误跳页（106）。这会直接造成用户所见内容不可信，
  比“给澄清 chips 多一点”更严重。
- **P1：共同规则缺陷**（知识库 50%、上一月、跳到、差异明细锚点）。修规则可同时
  提升两种模型，收益最大且不依赖 prompt 运气。
- **P1：小模型看板 20% / 整改 70% / 域内误拒**。修复前不能再宣称“小模型可完全
  替代主模型”；保留主模型回退与规则兜底是必要的。
- 本轮只增加评估与记录，**未改生产行为**。后续修复必须逐条带回归测试，并同时
  复跑 130 条，避免修好一类、弄坏另一类。
