# 开发日志 37 · 本地小模型部署与三模型对照

日期：2026-11-13

## 背景

小模型架构定位（模糊语义归一化器）获认可后，答辩需要实证：本地小模型能否
真正承担分类角色。选型 **Qwen3.5-9B**（千问 3.5 小尺寸系列，官方定位
"性价比极高的通用模型"），本地 llama.cpp CPU 部署（评测机无独显，内存 15.3GB）。

## 部署链路（全程可复现）

- 推理引擎：llama.cpp `llama-b12340-bin-win-cpu-x64.zip`（25MB，GitHub 发行包）；
- 模型：`unsloth/Qwen3.5-9B-GGUF` 的 **UD-Q2_K_XL**（3.84GiB，hf-mirror 下载；
  可用内存仅 4.5GB，Q4_K_M 的 5.8GB 装不下——如实记录选型约束）；
- 服务：`llama-server --alias qwen3.5-9b-local --port 8001 --ctx-size 4096
  --threads 8 --temp 0.0 --jinja --chat-template-kwargs '{"enable_thinking":false}'`
  （一键脚本 `scripts/start_small_model.cmd`）；
- 接通：`.env` 写入 `LLM_SMALL_*` 三件套，`LLMClient(role="classification")`
  自动路由到本地端点，`role_actual=small-model` 如实标注。引擎与模型不入 git。

## 两个真实故障与排除

1. **思考模式耗尽输出预算**：默认配置下模型把 token 预算全部烧在
   `reasoning_content`（思考链），`content` 为空、生成 984 token 不停，
   30s 角色超时全部打满。排除：`--chat-template-kwargs '{"enable_thinking":false}'`
   关闭思考 → 单次分类 22s→**3.5-4s**，直接输出合规 JSON。
   （Unsloth 文档称 Qwen3.5 小模型默认关思考，实测该 GGUF 在 llama.cpp b12340
   上默认开——文档与实现不一致，以实测为准。）
2. **nav 细分误判（3/26）**：基线 23/26 = 88.5%。"去看整改追踪"判域外、
   "切换到对标分析"判 benchmark、"把那个红的打开看看"判域外。
   探针实验（现版 prompt vs 补示例 prompt 直打服务端）证明是**示例缺失**而非
   能力上限：补 3 条域内 nav 示例 + 1 条"切换页面 vs 内容诉求"辨析后
   **26/26 = 100%**。DeepSeek 同 prompt 复跑 26/26 零回归——示例对强模型无扰动，
   对小模型是关键杠杆。

## 三模型对照（26 条模糊语义评估集，`scripts/agent_fuzzy_eval.py` 可复跑）

| 分类器 | 通过率 | 单次分类延迟 | 说明 |
|---|---|---|---|
| 纯规则兜底（--no-llm） | 19/26 = 73.1% | <1ms | 关键词表外表达落四入口 |
| DeepSeek 主模型（API） | **26/26 = 100%** | ~0.9-1.1s | main-model-fallback |
| **Qwen3.5-9B 本地（CPU）** | **26/26 = 100%** | ~3.5-4s | small-model |

域外拒绝两模型均 4/4（DeepSeek conf 0.98 / 9B conf 1.0）。
小模型组分层分布：llm 22 / llm-out-of-scope 4，无一规则仲裁。

## 结论与边界

- "小模型=模糊语义归一化器"的架构定位**实证成立**：9B-Q2 在 CPU 上即可达到
  与 DeepSeek 主模型一致的路由准确率，延迟可接受（交互阈值内）；
- 边界如实记录：①9B 需要 prompt 示例杠杆才到 100%（基线 88.5%），
  小模型对 prompt 工程更敏感；②UD-Q2_K_XL 是内存约束下的量化妥协，
  更高量化（Q4_K_M）需 ~7GB 空闲内存；③服务未启动时分类落规则层兜底
  （73.1%），`LLM_SMALL_*` 留空才回退主模型——两种降级路径行为不同，均已实测。
- 回归证据：pytest 229 全过（分组跑完，本机负载下 generate 组耗时较长属环境性）。
