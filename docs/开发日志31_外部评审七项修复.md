## 修复 1 · Dockerfile 引用不存在目录导致构建必炸

- **指控**：`Dockerfile` 第 42 行 `COPY data/kb/ data/kb/`，但交付包净化后无此目录，评委从零构建必失败。
- **核实**：属实。净化后 `data/kb/` 为运行时派生目录，不在仓库内。
- **参考案例**：scaife-viewer 的 ES 索引哨兵门控模式（`.es_indexed` 哨兵文件决定是否重建索引）；Docker 官方 entrypoint 幂等初始化惯例。
- **方案**：删除 COPY 行；`.dockerignore` 排除 `data/kb/`；`scripts/docker_entrypoint.sh` 改为"chunks.jsonl 缺失则从挂载的语料目录现场 `build_index()`"；HEALTHCHECK `start-period` 60s→240s（覆盖现场构建耗时）。
- **优点**：交付包与仓库一致，任意干净环境 `docker compose up --build` 即可起；索引与语料永远同源，杜绝"索引陈旧于语料"的漂移。
- **缺点**：首次启动多 1–2 分钟建索引（健康检查窗口已覆盖）；语料目录挂载缺失时启动会失败并给出明确报错（fail-fast，比带病运行好）。
- **验证**：`docker compose down -v` 删卷后从零 `up --build --wait`，三容器全部 Healthy；容器日志确认"索引缺失→现场构建→351 块"；`/api/products` 出数、前端 200。本机磁盘索引丢失时也用同一代码路径重建成功（31.6s / 351 块）——一条路径两处验证。

- **优点**：评委照 README 即可复现环境；诚实文档是评审信任的基础。**缺点**：无（纯文档修正）。
- **验证**：净化后回归 180 项 pytest 全绿（修复 5 新增 1 项版式锚定测试），vitest 76 全绿。

## 修复 3 · 校验器只查归因段，摘要/建议裸奔

- **指控**：`verify_report` 只对 `causes[].detail` 做数字白名单校验，summary 与 suggestions 的数字不校验，LLM 幻觉可绕过。
- **核实**：属实。
- **参考案例**：ragas faithfulness 指标（生成文本逐句对源核验）；guardrails 输出校验管线；protectyr-labs/attack-validator 的三级裁决（与既有 pass/auto_fixed/rejected 同构）。
- **方案**：`generate.py` 新增 `_check_text_numbers()`（summary/suggestions 数字过白名单）；`verify_report` 加 `require_citation` 参数 + 空归因闸门 + 全文零引用闸门；`report_gen.py` 仅对 LLM 轨强制引用（模板句轨强制引用即造假）；prompts 加铁律 10。
- **优点**：幻觉拦截面从归因段扩到全文；三级裁决语义不变，向后兼容。**缺点**：LLM 轨若模型不输出 citation 会被拒（有意为之——宁可拒稿不可造假）；mock 测试需按新契约带真实引用。
- **验证**：新增 5 项负例测试 + 全量 180 项全绿。

## 修复 4 · 报告整改清单编号与 RPA 系统两张皮

- **指控**：`report_data.py` 原造 `ZG-{month}-{i:02d}` 假编号，报告里的任务号在 RPA 系统查无此任务。
- **核实**：属实。
- **方案**：`_rectify_tasks` 改为按标题精确匹配 `act._sent_records()` 取真实 RPA task_id；未下发的标"待下发"，永不虚构编号。
- **优点**：报告与 RPA 系统同一身份，评委可拿报告任务号去 RPA 接口查证——可查证性是本赛题核心。**缺点**：报告中部分任务显示"待下发"而非编号（这是诚实的代价）。
- **验证**：测试重写为先清空残留记录→断言"待下发"→插入真实任务→断言统一→恢复现场；全绿。

## 修复 5 · PDF 版式三宗罪（目录无页码 / 页脚"共14页"穿帮 / 表格挤爆）

- **指控**：TOC 域不刷新、NUMPAGES 域在分节重排页码下算错、建议表列宽失控。
- **核实**：三条全部属实，实机目检复现。
- **方案**：`render.py` 新增 `_enable_update_fields`（w:updateFields 让 LibreOffice 刷新页脚域）+ 两遍转换链（`_outline_headings`→`_heading_pages` pypdfium2 逐页定位→页码口径换算→`_write_static_toc` 静态目录：dot leader、级别缩进、一级加粗）+ 末遍校验 `_footer_total_mismatch`，不符则 `_freeze_numpages` 冻结为静态值转第三遍；建议表/任务表固定列宽。
- **优点**：目录页码与正文物理页严格一致；页脚"第X页 共Y页"不再穿帮；表格版式稳定。**缺点**：转换次数最多三遍，单份报告多花十几秒；静态 TOC 不再可点击跳转（答辩场景可接受）。
- **踩坑记录**：①pypdfium2 不 `close()` 会锁文件（Windows）；②NUMPAGES 域藏在页脚文本框 `w:txbxContent` 里，`footer.paragraphs` 摸不到，须 `footer._element.iter(qn("w:p"))`；③域分段替换只冻 NUMPAGES 保留 PAGE。
- **验证**：实测产物 10 页、页脚一致、TOC 21 条带页码，截图目检通过；新增 `test_report_layout_fields` 锚定。

## 修复 6 · 评测报告不符合赛题 5.1.4/5.3.3 格式

- **指控**：现有四份评测文档均为"AI 自测"，缺赛题规定的三场景格式。

## 修复 7 · git 历史含赛题数据派生文件

- **指控**：仓库历史中含 `data/kb/` 索引、`reports/` 产物、`docs/e2e/` 截图（含真实数据）。
- **核实**：属实。用户裁决：只净化，不发布。
- **方案**：`git bundle` 全量备份（72MB）→ `.gitignore` 追加三类目录 → `filter-branch --index-filter` 全历史移除 → 删 `refs/original` 备份引用 → `reflog expire` + `gc --prune=now`。
- **踩坑记录**：①filter-branch 要求工作区干净，`reports/` 磁盘文件先移走再操作，净化后移回（**未丢失任何评测证据**）；②`refs/original/` 不删则旧对象仍可达，净化形同虚设；③`docs/e2e_uvicorn.log` 这类"前缀相似但非目录"的文件第一次漏网，二次净化补齐；④净化副作用导致磁盘 `data/kb/` 丢失，用修复 1 的同一重建路径 31.6s 恢复（351 块）——派生文件可重建的设计自我验证。
- **验证**：`git rev-list --objects --all` 全历史 grep 零残留；23 个提交完整保留；磁盘证据文件完好；回归 180+76 全绿。

## 补记（同日）：出处渲染缺口——修复 3 只修了一半

- **发现**：按"预生成"方案用 LLM 轨重产评测场景 B/C 报告时，核验正文发现：校验器确认 citations 字段合法（B=pass、C=auto_fixed），但**渲染层从不把 chunk_id 写进正文**——评委读报告看不到任何出处，"引用知识库"评分子项在纸面上不可见。
- **根因**：`_verify_sections` 只校验结构化 citations 字段；`render_docx` 只写 `sec.text`，citations 悬空。
- **方案**：`report_gen.py` 新增 `_attach_citations()`——LLM 轨校验通过后，把每段声明的 chunk_id 解析为"《文档名》p页码"章节名""行内追加到段尾（不换行，不占版式；模板句/被拦截轨不经过）。
- **优点**：出处落地确定性强（代码解析，不依赖模型自觉写《》）；校验→追加的顺序保证追加内容不参与再校验，页码属知识库元数据而非数据证据。**缺点**：出处集中段尾而非逐句内联，粒度略粗；同段多处引用同来源会去重合并。
- **验证**：`test_llm_track_with_mock` 追加 3 条断言锚定（出处格式/页码/文档名）；重产 B/C 报告核验：板蓝根 1 处出处、六味 3 处出处，全文零模板句标注，章节完整度复核 22 条零缺失。全量 pytest 180 项全绿。
- **评测报告同步**：场景 B/C 升级为 LLM 轨并附新证据重评，归因合理性自评 4.3→5.0；局限声明如实记录"初版为模板句轨、本版已重产"。
