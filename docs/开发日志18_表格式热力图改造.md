# 开发日志 18 · 热力图 → 表格式热力图（方案二 + 产品分区）

日期：2026-09-21 · 范围：`web/src/heatTable.ts`（新）、`web/src/components/HeatTable.vue`（新）、`web/src/charts/options.ts`（拆）、`web/src/views/DashboardView.vue`、`web/src/__tests__/{heat-table.test.ts（新）, linkage.test.ts, options.test.ts}`

## 决策（四段式）

- **决策**：用户选定方案二（条件格式数据表）并要求**按产品分区**。落地为：ECharts 热力图整体退役，同一份 `/api/charts/heatmap` 数据改由纯 HTML 表格渲染——数字直读 + 色阶底色双通道；产品以 `rowspan=3` 分区列 + 区间 2px 粗分隔线表达；保留全部联动（点击格子切换看板、当前 产品×月份 描边+柔光高亮、null 首月显示"—"）；色阶/分组/选中判定全部抽 `heatTable.ts` 纯函数（与 CT.heat 同色板，量程口径与原 visualMap 一致：ceil 最大绝对值）。原 `heatmapOption` 及其测试拆除，语义测试迁至 `heat-table.test.ts`（7 项）。
- **优点**：可读性天花板（数字+色彩双通道，财务评委零学习成本）；少一块 canvas，少一类 ECharts 配置陷阱（此前"悬停选中格 tooltip 崩溃"这类 bug 在纯 DOM 下不可能发生）；产品分区彻底回答"9 行挤一起"的混乱；打印/截图进报告整齐；表格天生响应式（横向滚动兜底）。
- **缺点**："图表感"下降——热力图作为加分项的视觉冲击力让位给报表感（缓解：标题保留"热力图（表格式）"，色阶表属热力图家族，且保留了完整联动与量程图例）；ECharts 依赖并未因此移除（趋势/结构/瀑布/蝶形仍在用）；色阶插值是自绘的（两桶线性），极端值被钳制在端色。
- **裁决**：值得。用户痛点是"不清晰、不美观"，方案二正面解决；联动手感实测无损。
