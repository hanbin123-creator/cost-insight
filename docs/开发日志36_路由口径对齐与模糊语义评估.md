# 开发日志 36 · 路由口径对齐与模糊语义评估

日期：2026-11-13

## 背景

答辩准备引入"小模型处理模糊语义"架构（小模型=模糊语义归一化器）之前，先验证
分类管线对模糊语义的真实有效性。新建评估 harness `scripts/agent_fuzzy_eval.py`：
26 条"不像指令的人话"用例，分 A 口语意图 13 / B 模糊指代 6 / C 域外 4 / D 边界 3 四组，
支持 LLM 主线与纯规则兜底（`--no-llm`）双模式对照，逐条落 JSON 明细
（`docs/_fuzzy_eval/`）。判定口径：路由正确性 ≠ 场景执行成功——意图命中 +
行为类别（exec/clarify/nav-any/out）符合预期即过，result.ok 另记不受外部服务影响。

## 基线实弹（对齐前）

- 纯规则兜底：18/26 = 69.2%——口语化表达大量落四入口，量化出规则层的能力天花板；
- LLM 主线（role_actual=main-model-fallback，尚未配小模型）：22/26 = 84.6%。

## 发现的两处口径不齐

1. **nav 动词口径两层打架**：规则层合同是"动词+页名/锚点双命中才 nav"
   （`test_heatmap_keyword_routes_dashboard` 等测试锁定），但 LLM 判别要点里写着
   "看下那个瀑布→nav"——"看下"不在 `_NAV_VERBS`，模型忠实执行 prompt 与规则层冲突，
   "看看热力图"被判 nav（设计口径应为 dashboard）。
2. **置信度校准缺口**：prompt 只有"拿不准给低分"，口语化但意图明确的表达
   （"最近成本咋样啊"0.6、"下个月成本会不会涨"0.55）被压到阈值 0.7 之下，
   正确意图被拦到四入口——4 条失败中 3 条属此类。与日志 25 的"提示词自伤"同源。

## 对齐措施（只改 prompt 文本，不动阈值 0.7、不动三层架构）

- 判别要点：nav 显式要求"打开/切换/跳转/去看"类跳转动词；"看看/瞅瞅某图"
  这类无动词的查看请求归场景意图（看趋势看图 → dashboard）——与规则层、
  测试锁定口径三方一致；
- 置信度：口语化表达（"咋样""瞅瞅""呗""会不会"）只要意图明确属域，
  confidence 给 0.75-0.9；仅意图本身确实无法判断时才给低分；
- 评估集自身口径修正：用例"那张趋势图给我瞅瞅"（无动词）从 B-模糊指代(nav)
  移到 D-边界(dashboard)——对齐后模型行为与规则层一致，是评估集原先的
  预期写错了，不是模型错了。

## 对齐后实弹

| 模式 | 对齐前 | 对齐后 |
|---|---|---|
| LLM 主线 | 22/26 = 84.6% | **26/26 = 100%** |
| 纯规则兜底 | 18/26 = 69.2% | 19/26 = 73.1%（LLM 增量 +26.9pp） |

域外拒绝 4/4（conf 0.98，域围栏稳定）；平均延迟 1.77s；路由层分布
llm 22 / llm-out-of-scope 4——无一回落规则仲裁，口径统一后两层不再打架。

## 对齐范围盘点（已核实一致，无需改动）

- 前端 `data-anchor` 15 处 ↔ 内容登记册 `CONTENT_TARGETS` 一一对应；
- README Agent 口径"动词+内容名直达页内锚点"与代码行为一致；
- `api.py` chat 注释、SCENES 描述、四入口 choices=6 与测试锁定一致；
- 测试无 prompt 文本断言，prompt 修订零回归风险（全量 pytest 229 复核通过）。
