# 开发日志 17 · 热力图选中高亮可读性修缮（"蓝框"疑义处理）

日期：2026-09-21 · 范围：`web/src/charts/options.ts`、`web/src/views/DashboardView.vue`、`web/src/__tests__/linkage.test.ts`

## 起因

用户截图提问"这个蓝色的框是什么"——热力图上 银黄口服液×2026-05 三格的蓝色描边。它本来是 F4 V4 联动的**设计行为**（当前看板所选中选中格描边），但裸描边视觉上像渲染瑕疵，且用户无从得知其含义。

## 决策（四段式）

- **决策**：保留描边语义（它承载"热力图 ↔ 看板选择"双向联动的视觉锚），做三件事：① 描边叠加主色柔光晕影（shadowBlur 7，rgba(46,109,164,.45)），让选中态读作"高亮"而非"出界错误"；② tooltip 对选中格加"✓ 当前看板所选"前缀——在疑惑发生的位置就地解释；③ 图表面板 hint 补一句"蓝色描边高亮 = 当前看板所选"。
- **优点**：语义不变、联动不破（既有描边测试全兼容）；解释出现在三个触点（视觉/悬停/常驻提示），用户不再需要问"这是什么"；顺带修复了一个真实 bug。
- **缺点**：柔光在投影/低亮度演示环境可能偏淡；tooltip 前缀让选中格浮层多一行（信息密度略降）。均可接受。
- **裁决**：值得。这是"用户看不懂的设计 = 设计失败"的典型修缮——不加新机制，只让既有机制自我解释。

## 顺带修复的真实 bug（本次排查发现）

tooltip formatter 原来假定 `p.data` 恒为数组；而选中格是 `{value, itemStyle}` 对象包装——**悬停高亮格时解构直接抛 TypeError，tooltip 崩坏**。此前所有测试都没覆盖"悬停选中格"路径（单测只断言描边存在，没调过 formatter）。已改为双形态兼容（数组/对象包装均可），并新增一条测试同时断言：选中格不炸 + 带前缀、普通格无前缀。这是"用户提问驱动发现深层 bug"的又一例。
