## 〇、前置修复：两位小数强制（A 阶段）

- **背景**：用户明确要求金额/比率"必须有小数，保留至两位"；实测发现 LLM 会把 11.63 写成"约 12 元"
- **决策**：三层防线——①prompts.py / report_gen.py 系统提示加铁律 8（原值完整引用，禁"约 11 元"）；
  ②generate.py 新增 `_numbers_with_units()` 单位守卫（只盯带"元/%"的数字，型号/年份不误伤）；
  ③verify_report 反馈循环加"精度丢失"检查：带单位整数 n 不在白名单、但白名单存在 |x−n|<1 的非整数 x
  → 报错附最多 3 个相近原值，模型照抄即收敛
- **优点**：提示层劝、校验层拦、反馈层教——三层次冗余，单一失效不致命；
  实弹复测板块3 verdict=pass（第一轮触发精度检查，第二轮照错误消息收敛），证明反馈教学有效
- **缺点**：单位守卫只认"元/%"，其他单位（吨、万）若未来出现需扩表；
  相近匹配窗口 ±1 是经验值，理论上存在恰压线的误判（实测未出现）
- **裁决**：做——精度是对账型评测的硬指标，"差不多"在评审眼里就是错

## 一、B1 生产者驱动改造（report_data.py 重写）

- **决策**：从"消费者断言兜底"翻转为"生产者声明驱动"——_Bundle 共享计算前置 +
  5 标量组 + 6 动态表组（_Group: name/provides/fn/extras）+ `_validate_groups()` 导入时校验
  （声明并集==注册表键集、组间查争抢，ImportError 打印差集）；`_assert_coverage` 保留为运行期兜底
- **优点**：漏键在 import 时刻爆炸而非报告产出后；新增计算组只需声明 provides，
  注册表对账自动化——"声明与实现对不上账"这类 bug 从结构上被消灭
- **缺点**：声明与实现存在受控重复（provides 列表与函数内赋值各写一遍，靠校验兜住）；
  代码变长几十行；发现孤儿键"波动告警描述"（只写不读、不在注册表）——归入 extras 保留，
  说明历史代码确有冗余，声明驱动把它照了出来
- **裁决**：做——受控重复换 import 即炸的确定性，值

## 二、B2 提取脚本独立化（template_scan.py + extract_placeholders.py）

- **决策**：占位符提取逻辑从测试辅助升级为独立模块 app/template_scan.py
  （extract_placeholders / diff_against_registry / classify_with_registry），
  scripts/extract_placeholders.py 提供 --check（漂移检测，退出码 1）/
  --write（重建注册表）/--template/--assign（人工归类）
- **踩坑记录**：初版启发式"独立段落→文本段"把"报告标题"误判为文本段（它是独立段落但实为标量）
  ——启发式无法 100% 可靠，改为 standalone_other 待判别桶，--write 遇待判别键拒绝落盘（退出码 2），
  由 --assign 人工归类后放行。**宁可卡住问人，不可猜错落盘**
- **优点**：漂移检测成为随时可跑的命令（演习 0.2s 出结果）；注册表可从模板重建，
  不再是"只能人肉维护"的单点；测试 test_registry_covers_template 改用同源提取，测试与工具不双轨
- **缺点**：--assign 是人工步，应急时多一次判断（但它卡住的恰是启发式必错的地方，人工是必要的）；
  --write 会把注册表重写为 sorted 顺序（集合等价，diff 噪声可接受）
- **裁决**：做——安全绳齐备后才敢让工具写代码文件

## 三、B3 L1 映射外置 YAML（mapping.py + placeholder_map.yaml）

- **决策**：模板键名 → 内部标准字段的映射从代码硬编码外置为 config/placeholder_map.yaml
  （89 scalars + 6 dynamic_tables + 6 text_sections + 3 条别名归一规则 ^当月→本月 等）；
  report_data.py 二次重写为只认标准字段 id（report.title / material.cost.current / rows.* 等）；
  Mapping 单例 import 即双层校验——①YAML 键（含别名命中）==注册表全集，缺键列清单写人话；
  ②YAML 值==代码声明字段集（report_data/report_gen 声明），对不上账列双向差集；
  render.py 经 MAPPING 翻译后渲染；路径支持 PLACEHOLDER_MAP_PATH / REPORT_TEMPLATE 环境变量覆盖
- **优点**：换模板 = 改 YAML，代码零改动；别名规则让"本月产量→当月产量"这类同义改名自动适配
  （演习中 5 个改名键有 2 个被别名接住）；双层校验让"YAML 与代码对不上账"在启动时刻爆炸，
  报错直接告诉运维补哪几个键——人话，不用读源码
- **缺点**：新增配置漂移风险面（YAML 改错代码不知道——靠双层校验对冲）；三层命名
  （模板键/字段 id/Python 变量）增加认知负担（靠校验和翻译层隔离）；import 即炸意味着
  配置错误时整个服务起不来——但这是设计意图：宁可起不来，不可带病跑
- **裁决**：做——这是模板可复用方案的核心枢纽，验收标准直接落在它身上

## 四、B4 转换重试（render.py）

## 五、B5 消防演习（fire_drill.py）——全程实测 9.1 秒

- **演习设计**：真实官方模板绝不被修改（变异发生在副本）；注册表会被 --write 真实重建
  （应急链固有动作），全程字节级备份、finally 强制恢复、恢复后 --check 复验——演习零残留
- **变异内容**：5 个占位符改名（本月产量→当月产量、上月产量→上期产量 ← 别名可接住；
  报告标题→报告名称、产品规格→产品型号、材料环比→材料环比变动 ← 需人工补 YAML）
- **实测计时**：

  |---|---|---|
  | ①漂移检测 | 0.2s | 5 个改名键全部报警，退出码 1 |
  | ②重建注册表 | 0.4s | --write 成功；1 个独立段落新键经 --assign 人工归类 |
  | ③映射校验拦截 | 1.1s | 3 个未映射键列入人话报错；2 个被别名自动适配并留痕 |

- **优点**：应急链每个环节都被真实演练过（不是纸面推演）；全程 9.1s 意味着赛方演示现场
  换模板也能当场面不改色地修复；安全绳（备份/finally/复验）经受住了两次真实崩溃考验

- **裁决**：做——演习中抓到的三个真 bug（见下）证明演习本身值回全部成本

## 六、演习抓到的三个真 bug（演习的最大产出）

### D21. Windows GBK 控制台炸掉 subprocess 解码线程【已修复】

- **现象**：演习首发阶段①即崩——子进程中文输出被父进程按 GBK 解码，
  解码线程抛 UnicodeDecodeError，stdout 变 None，断言 TypeError
- **决策**：_run 双保险——子进程注入 PYTHONIOENCODING=utf-8 + 父进程 encoding="utf-8"
  errors="replace" 兜底
- **缺点**：无实质缺点；errors=replace 理论上会吞掉乱码证据（但乱码本身已不可读）
- **教训**：Windows 上任何 subprocess 调中文输出程序都必须显式指定编码——默认 GBK 是定时炸弹

### D22. 映射校验失败时别名命中证据被吞【已修复】

- **现象**：阶段③预期看到"别名归一命中"警告，实际只有 ImportError——
  警告 print 在 _validate 的 raise 之后，爆炸路径上证据丢失
- **决策**：警告 print 前移到 raise 之前（_print_warnings 独立方法）——**警告先于爆炸留痕**
- **缺点**：无；纯顺序修正
- **教训**：报错路径上的诊断信息必须先输出再抛异常，否则最该看到的信息恰好在出事时消失

### D23. 证据复制 SameFileError【已修复】

- **现象**：阶段⑤产物本就直接落在证据目录，脚本又多复制一次到自己—— shutil.SameFileError
- **决策**：删除多余复制步骤，注释说明产物即证据
- **缺点**：无
- **教训**：路径相对/绝对混用时"源==目标"不易察觉，复制前自问一句"它是不是已经在那了"
