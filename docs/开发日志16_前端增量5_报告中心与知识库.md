日期：2026-09-21 · 范围：`app/api.py`（+3 端点）、`tests/test_api.py`（+5 测）、`web/src/{types.ts, api.ts, archiveHelpers.ts}`（新）、`web/src/views/{ReportsView.vue, KbView.vue}`（新）、`web/src/{App.vue, views/DashboardView.vue}`

## 决策（四段式）

- **决策**：
  1. **先补后端缺口再写页面**——实测确认两个缺口：`GET /api/reports`（归档清单）与 `GET /api/kb/query`（检索透明化）不存在，另补 `GET /api/reports/{filename}` 下载。归档端点扫 `reports/` 按同 stem 归组 docx/pdf、mtime 倒序；命名不合规文件列入 `unknown_files` 如实暴露；下载端点路径穿越与改后缀文件一律 422/404。
  2. **F8 报告中心**：顶部新建操作条（月报/季报/专题 → 参数弹窗 → 生成中提示约 1–3 分钟 → 完成入轴）+ 时间轴归档（主题色节点：月报蓝/季报紫/专题琥珀）+ 首页最新报告卡（V4，失败静默隐藏）。
  3. **F10 知识库**：检索优先大搜索框，命中卡带三路通道 chips（向量/关键词/图谱）+ RRF 分 + 页码章节出处；文档表格（大小/索引块/版本/覆盖态）+ 上传（base64 分块编码防栈溢出）+ 删除；job.state 四态如实映射。
  4. 格式化/校验/映射全部抽纯函数 `archiveHelpers.ts`，13→10 项单测先行。
- **优点**：前端零计算（排序在服务端、格式化是纯函数）；检索透明化把 RAG 三路召回收敛成评委可见的证据链（命中通道+出处+分数），正中"结构化图谱构建/可解释"加分点；参数弹窗校验纯函数化，422 文案用户可读；上传/删除后自动两轮刷新让重建状态尽快可见。
- **缺点**：归档列表基于文件名解析，产品名若未来含下划线会解析失败（已右切两段+unknown 兜底，且产品名口径来自数据包不含下划线）；报告生成是长任务但走同步等待（1–3 分钟按钮转圈），无后台任务队列——竞赛数据量下可接受，企业版演进为 Celery/任务表；上传无大小上限校验（后端 base64 解码即收，企业版需补）；mtime 显示依赖本机时区。
- **裁决**：值得。缺口端点是前端收官的硬前提，先补后端避免了"前端造假数据"；同步生成在演示路径上反而更稳（无队列状态机失分面）。
