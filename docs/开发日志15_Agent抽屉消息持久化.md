# 开发日志 15 · Agent 抽屉消息持久化（方案 A：localStorage 本地存档）

日期：2026-09-21 · 范围：`web/src/chatPersist.ts`（新）、`web/src/components/AgentDrawer.vue`、`web/src/__tests__/chat-persist.test.ts`（新）

## 决策（四段式）

- **决策**：Agent 抽屉对话采用 localStorage 本地存档。键 `ci-agent-chat`，结构 `{version:1, messages, savedAt}`；每条消息额外记 `ctx:{product,month}` 与 `ts` 时间戳；只保留最近 50 条（超出裁最旧）；抽屉挂载即恢复，任何 push 即时落盘；所有 localStorage 操作 try/catch，隐私模式/配额满静默降级为"不持久化"；消息上下文与当前筛选不一致时气泡角落显示灰色小标签；头部加"清空"按钮（免二次确认）；决策卡状态**不持久化**，每次打开重新求值；序列化/裁剪/标签判定全部抽纯函数进 `chatPersist.ts`。
- **优点**：刷新/关页重开对话不丢（用户实测痛点解决）；零后端改动、零新依赖；纯函数 13 项单测覆盖容错路径（JSON 损坏、脏数据逐条剔除、配额满抛错、版本不符）；ctx 标签让"跨产品问过的旧消息"不产生误读；空存档直接删键不留空壳。
- **缺点**：换浏览器/清缓存即丢（localStorage 天性，方案 A 已声明）；50 条上限意味着长会话会丢最早记录；消息以明文存本机，若未来接入敏感数据需再评估；深度 watcher 每次 push 全量序列化（50 条上限下体积约数十 KB，可忽略）。
- **裁决**：值得。竞赛演示与企业单机试用场景下，本地存档的收益（不丢对话）远大于其限制；未来企业版若需跨端同步，换后端会话表即可，`chatPersist.ts` 的纯函数层不变。

## 实测中抓到并修复的一个真 bug

第一版清空时：`clearChat()` 删键后，`messages.value = []` 触发深度 watcher 又把**空数组存档写回**了 localStorage——键没被真正删掉。功能无害但语义不干净。修正：`saveChat` 收到空列表时直接 `removeItem`，并补一条单测锁死该行为。这正是"先实测再交付"的价值：单测全绿也没拦住这个交互层面的回写，浏览器 E2E 抓出来了。
