## 一、前端工程落地（Vue3 + TS 严格模式 + vue-echarts）

### 结构决策
- **决策**：四层——`api.ts`（请求集中）→ `types.ts`（契约类型）→ `charts/options.ts`
  （数据→option 纯函数映射，vitest 主战场）→ 组件薄渲染（ChartPanel 三态：加载/错误/图表）
- **优点**：渲染逻辑 100% 可在 node 环境单测，不依赖浏览器；纯函数无副作用，
  恶意用例（负瀑布、首月 null）直接灌 fixture 断言
- **缺点**：options.ts 与后端 charts.py 存在"契约漂移"风险——靠 fixture 导出脚本
  （export_fixtures.py 从真实 API 响应固化）+ 契约测试双锚定缓解，但仍是人工触发，
  忘跑就会漂（列入联调 checklist）
- **裁决**：接受——漂移风险用流程兜底，比把计算塞进组件强得多

### 演示模式（LLM 未配置时的诚实兜底）
- **决策**：点击「生成归因分析」→ 后端 503 → 前端加载 `demo_attribution.json`
  （MockLLM 走完整校验闭环后固化的样例）+ 页面显著标注"演示模式（样例数据，LLM 未配置）"
- **优点**：无 key 环境下评委仍能完整看到三重校验闭环的工作产物（含 badge、auto_fixed 明细）；
  样例本身经过校验，不是编造的海市蜃楼
- **缺点**：演示样例与实时数据无关（银黄口服液 2026-05 固化），用户切换产品后
  若不注意标注可能误以为是对应产品的分析——靠"切换即清空 report"缓解
- **裁决**：值得——展示完整性 > 样例时效性，且标注义务已落到 UI

## 二、E2E 浏览器实测（headless Edge + Playwright）

### 方案
`scripts/e2e_browser_check.py` 单命令全包：起 uvicorn(8000)+vite(7100) → 等端口 →
headless Edge 开看板 → 8 项断言 → 截图存证 → finally taskkill 整树清理（零后台残留）。
断言含像素级验证：读 canvas ImageData 统计非白非透明像素，阈值 800（坐标轴本身仅几百）。

### 实测发现并修复的 6 个真实问题
1. **Windows PIPE 死锁**：子进程 stdout=PIPE 无人读取，缓冲满后 vite 永久阻塞 90s 超时。
   → 改重定向到日志文件（docs/e2e_*.log）
2. **vite 仅监听 IPv6**：`localhost` 在 Windows 解析为 ::1，探测脚本连 127.0.0.1 误判未就绪。
   → 显式 `--host 127.0.0.1`
3. **切换中间态截到空坐标轴**（最严重）：首次截图里四图"有轴无图"——canvas 存在≠图形已绘制；
   决策横幅先返回、图表仍在加载。→ 断言升级：等所有 `.state` 占位消失 + 800ms 动画缓冲 +
   像素量阈值。这暴露了"DOM 断言够不到 canvas 内容"的盲区，像素断言是必要补充
4. **结构图外圈标签互叠**：8 项物料标签挤在一起。→ 三级修复：labelLayout.hideOverlap
   （隐藏放不下的）+ 饼心上移 44%（底部让位给 legend）+ 占比 <5% 不显示文字标签
   （tooltip 仍可查）。占比用 ECharts 内部 percent，仅做显示判断，不违"下游不计算"
5. **graphic 水印组件未注册**：`[ECharts] Component graphic is used but not imported`
   （console 错误被 E2E 捕获）。→ main.ts 补 GraphicComponent
6. **置信带图例色错位**：band 系列走默认调色板显示绿点，与紫色带体不符。→ 显式 itemStyle

### 优缺点
- **优点**：每个问题都有截图/日志证据；像素断言把"看起来渲染了"变成可重复验证的
  数字门槛（当前四图 16035/31111/29376/69434 像素）；脚本可重跑，评委演示前可自检
- **缺点**：像素阈值是经验值（800），换主题/尺寸可能需调整；headless Edge 与评委真实
  浏览器仍有差异（字体、DPR）；E2E 未覆盖归因 rejected 拦截态的 UI（缺真实 rejected 样例——
  因 MockLLM 样例质量高，真实拦截需接真模型后补测）
- **裁决**：必须做——首次 E2E 就抓到 3 个致命渲染问题，证明"构建通过+单测通过"远远不够

## 三、预测延伸带（加分项 · 演示级）

### 后端 forecast.py
- **决策**：Holt(trend='add', damped) 只用 2026 年 6 个连续点外推 3 个月；
  置信带 80% 用 simulate 模拟法（2000 条路径取 10/90 分位，random_state=42 可复现）；
  同比对照线（近两月同比率均值恒定外推）；clip 护栏 [min×0.5, max×1.5] + clipped 标记；
  note 强制标注"演示级，不作决策依据"
- **优点**：阻尼防止 6 点噪声趋势无限发散；双方法印证/背离本身就是分析素材
  （银黄口服液实测：Holt 看平 ~11.2，同比对照看涨 ~12.5——评委能直观看到方法差异）；
  随机种子固定 → 测试可精确断言；clip 兜底物理不可能值（负成本）
- **缺点**：6 个观测点无法估计季节性与结构拐点，置信带宽、精度有限；
  simulate 2000 次约 0.3s/产品（lifespan 预加载单例，摊销后无感）；
  statsmodels 0.15 的 HoltWintersResults 无 get_prediction（statespace API），
  初版误用已修正——文档与代码注释均留痕
- **裁决**：定位"展示预测能力框架"而非"精准预测"——方法诚实 + 护栏齐全 + 强制标注，
  优于不做或夸大

### 下游永不计算的延伸
- 置信带堆叠差值（upper−lower）、虚线与历史线衔接点、同比对照线坐标——全部后端预计算
  （`band_diff_line`/`forecast_line`/`yoy_line`），前端只做 stack 摆放；
  vitest 断言 `lower + diff ≈ upper` 闭合，api 测试断言同一闭合——双端对账
- 前端 trendOption 第二参数可选：预测加载失败时趋势图照常渲染（增强层降级不阻断主流程，
  console.warn 留痕）——这是对三态纪律的显式豁免，理由是"预测失败不该拖死主图"

### 前端展示
虚线（Holt 紫）+ 点线（同比对照棕）+ 半透明置信带 + 右下角"预测为演示级"水印；
x 轴扩展 2026-07~09；历史线尾部补 null（摆放，非补 0）。
