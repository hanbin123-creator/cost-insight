## 一、总体决策

- **决策**：报告 = 代码组装（89 标量 + 6 动态表 + 2 嵌图 + 整改任务）+ LLM 只写 6 个叙述段落；
  渲染走 docxtpl 标量替换 → 哨兵段落 → python-docx 插真表/嵌图；无 LLM 时模板句兜底
- **优点**：报告 90% 内容（数字/表格/图）零幻觉空间；LLM 暴露面压缩到 6 个段落，
  且每段仍过三重校验；官方模板原样使用（101 占位符实测提取，未自创格式）
- **缺点**：模板硬编码（表头/五类制造费用/键名映射）与官方模板强耦合——模板改版要改代码；
  用注册表漂移检测测试兜底（test_registry_covers_template 重提占位符比对，改版即红）
- **裁决**：接受耦合——赛题交付针对固定模板，漂移测试把隐性耦合变成显性报警

## 二、关键机制

### 2.1 占位符注册表（101 = 89 标量 + 6 动态表 + 6 文本段）
- 从官方 docx 实测提取生成 `report_registry.py`，`_assert_coverage` 在每次组装后自检：
  缺一个键直接 AssertionError——"漏填占位符"这类静默缺陷在开发期爆炸
- 实测立即立功：模板命名不一致（材料→`本月材料成本`、人工→`本月人工成本`、
  制造费用→`本月制造费用`，无统一后缀），按想当然命名必错，自检当场抓住

### 2.2 校验器三处升级（generate.py，模块2 同步受益）
1. **舍入变体入白名单**：每个数值按 1/2/3/4 位小数同时入册。
   起因：对标 description 预生成文本引用 13.2（存储 13.16）被误判编造——
   校验目标是拦"无中生有"，不是拦"合理舍入"
2. **绝对值变体入白名单**：方向词承载符号（"低 7.8%" ← 存储 −7.8），绝对值不是新数字
3. **±N% 阈值常量豁免**：告警消息内的"±10%"是配置常量不是数据证据
- **优点**：根治 display-rounding 类误报（本轮实测 3 类 8 个），模块2 真实 LLM 接入后
  同类误报同步消失；extra_allow 参数让对标树数字合法化而不污染主白名单逻辑
- **缺点**：白名单膨胀约 8 倍（~500→~4000 浮点），编造数字撞库概率理论上升；
  编造拦截测试（999.9）锚定防退化
- **裁决**：值得——误报是声明制可用性的最大敌人（决策 F 的延续），
  而撞库编造需要模型"恰好猜到白名单数值"，概率与危害都低

### 2.3 文本段落双轨
- 有 LLM：一次调用产 6 段 + 建议，声明制 + 反馈重试一轮（复用模块2 全部机制）
- 无 LLM：代码模板句（全部数字取自产物包），报告中保留"（模板句·LLM未配置）"标注；
  API 层无 LLM 返回 200 而非 503——报告主体不依赖模型，降级透明可演示
- 实测：模板句初版被自己校验器判 rejected（0.203 舍入/计数"1 条"/阈值"±10%")——
  自证校验器有效，且推动了三处升级
