# 开发日志 26 · 交付要求一「一键启动」三缺口修复

日期：2026-09-22

## 背景

对照交付要求一（Dockerfile/requirements.txt 一键启动 Web 服务）实测核查发现三缺口：
① README 停留在脚手架期（无 Web 启动说明）；② compose 链路从未实机验证（本机无 Docker）；
③ mock RPA 不在 compose 编排内（"一键"变两步）。

GitHub 案例调研（2026-09-22 检索）：
- [fastapi/full-stack-fastapi-template](https://github.com/fastapi/full-stack-fastapi-template)
  （45.7k 星）：README 徽章置顶 + `test-docker-compose.yml` CI 真机冒烟（build →
  `up -d --wait` → curl 端点 → `down -v`）——CI 即实机验证，徽章即证据；
- `docker compose up --wait` 在 GitHub Actions 中 4208 个工作流命中（行业标准）；
- compose `profiles`/override 可选 mock 服务 2324 命中（OpenCTI/mokapi、cordum 等）。

## 决策（按 3→2→1 落地）

1. **缺口3**：新增 `docker-compose.rpa.yml` 覆盖文件——`mock-rpa` 服务
   `build: ../创灵境_考题模拟数据/05_RPA接口文档`（官方 Dockerfile 现场构建，仓库零接触
   数据包，保密红线不破），并覆盖 `RPA_BASE_URL=http://mock-rpa:8090` + 健康检查；
   基础 compose 的 `web.depends_on` 升级为 `condition: service_healthy`。
   选覆盖文件而非 profiles：profiles 无法按开关切换 app 的环境变量，覆盖文件可以。
2. **缺口2**：新增 `.github/workflows/compose-smoke.yml`（照搬模板范式）+
   `docker-compose.ci.yml` 覆盖层（占位数据挂卷）+ `scripts/make_placeholder_data.py`
   生成器（纯合成值，表头对齐考题包）。**实机验证从"本机装 Docker"转移为
   "GitHub runner 每次 push 真机跑"**——这是行业范式，也绕开本机装不了 Docker 的现实。
3. **缺口1**：README 重写——徽章置顶、一键启动 30 秒可见（Docker/本地/无数据包预览
   三段式）、功能地图、测试矩阵、合规说明；脚手架期化石描述全部清除。

## 优点

- 评委路径最短化：一条 `compose up --build`（要整改闭环加 `-f ...rpa.yml`）；
- 一键启动的"可达性"从此有 CI 持续背书，不靠人肉回忆；
- 占位数据零警告过 ingest 全部硬校验（生成器第一次还因制造费用明细行少一列被
  DataIntegrityError 拦下——校验前置设计再次自证有效）；
- 保密红线、断网降级设计全部保持（CI 环境无 LLM 密钥，顺带验证了降级路径）。

## 缺点

- 占位数据需随考题包表头演进维护（表头变了生成器要跟着改）；
- CI 冒烟只证"起得来、端点活"，不证"数字对"（分工：数字归 pytest 对账）；
- **本机 Docker 安装失败，本地 compose 实机验证仍是缺口**（见下）；
- compose 覆盖文件要求评委目录结构与约定一致（README 已写死）。

## 本机 Docker 安装尝试（如实记录）

- 无 winget、无 WSL2（Docker Desktop 的前置）；
- 官方安装包 625MB，实测下载速率约 107KB/s（280s 仅 30MB），完整下载约 97 分钟；
- 即使下载完成：静默安装需 UAC 管理员提权、WSL2 安装需重启、守护进程首启需交互登录。
- **结论**：本机自治安装不可行，放弃；半截安装包已清理。实机验证走两条路：
  ① 仓库发布到 GitHub 后 compose-smoke 自动跑（已就位）；② 任何有 Docker 的机器
  按 README 一条命令（评委路径本来如此）。

## 验证

- 占位数据：生成后 `init_store()` 零警告，3 产品 × 6 月 × 双厂全部入库；
- 三份 YAML（compose×2 覆盖 + workflow）语法+关键语义断言通过
  （depends_on condition / build 路径 / RPA_BASE_URL 覆盖）；
- pytest 172 全绿（本次改动不触及 app 代码，回归确认无侧伤）；
- compose 实机 `up --build`：待 GitHub 发布后由 CI 背书（本机无法验证，如实标注）。
