## 一、架构执行（按方案 V2 主从修正版，零偏差落地）

```
用户自然语言 → ①小模型分类主线（json_mode 强制 {"intent","confidence"}）
  → confidence ≥ 0.7（config）→ Pipeline 场景执行
  → LLM 未配置/失败/破损 JSON → ②规则关键词兜底（layer="rule"）
  → 低置信/双不中 → ③四入口卡片（不猜，让用户选）
```

- **LLMClient role 路由**（手册 6.3 另一半兑现）：role="classification" 读
  LLM_SMALL_* 三件套；未配置回退主模型，`role_actual` 如实标注
  "small-model" / "main-model-fallback"——多模型协作加分项的载体就位
- **路由只做分发永不算数**：参数抽取规则化（产品别名枚举 / 月份正则），
  抽不出返回澄清问题，绝不编造；场景执行经 Pipeline（阶段0 落点）
- **"不猜"是双向约束**：模型低置信（conf>0 但 <0.7）时规则层不得凌驾——
  test_low_confidence_not_overridden_by_rules 锚定：模型说"我没把握"，
  系统不能拿关键词硬猜一个意图执行

## 三、实弹抓到的真问题（D26）

- **现象**：首发实弹第一句就卡住——用户口语"五月份"是中文数字，
  `_extract_month` 只认阿拉伯数字，月份抽不出 → 澄清反问（功能正确但体验拉胯）
- **决策**：月份抽取补中文数字映射（一~十二月，含"十一/十二"组合）
- **优点**：真实口语覆盖；中文数字表枚举制不猜测（"十三月"抽不出，落澄清）
- **缺点**：中文数字歧义场景存在（"十月怀胎"会误抽 10 月）——接受：
  误抽后结果页会显示月份，用户可见可纠正；且上下文为成本分析对话
- **裁决**：做——实弹第一发就抓到，再次证明实弹不是仪式
- **测试锚定**：五月份→2026-05、十一月→2026-11

## 四、阶段2 缺点（自曝）

1. **单意图假设**：复合请求（"出报告并下发整改"）只路由最高分意图——
   多意图编排是企业演进版能力；竞赛版答辩口径"一次一件事，路径可预期"
2. **规则兜底关键词表维护成本**仍在（但已退为兜底，漏了落四入口不致命）
3. **小模型端点未实弹**（LLM_SMALL_* 未配置，role 路由逻辑已单测锚定，
   真实小模型端点留待部署环境验证）
4. **置信度阈值 0.7 是经验值**：DeepSeek 实弹全部 0.92+，未观察到 0.4-0.7 区间
   的真实样本——阈值有效性待更多真实语料校准（config 可调，不硬编码）

## 五、域围栏加固（D27，用户要求"限制大模型，防止思考别的"）

- **盘点结论**：系统四个 LLM 触点中三个已被结构锁死（归因/报告的输入只有
  代码 JSON + 输出双闸；任务润色双闸）——唯一有跑题风险的是意图分类器，
  原 prompt 只说"拿不准给低分"，没给域外请求一个正式出口
- **决策**：意图枚举四 + 显式 `"none"`（域外出口）——分类纪律改为：
  域外请求必须输出 none，禁止硬归四意图，禁止靠"置信度碰巧低"蒙混；
  none 命中时 layer 如实标 `llm-out-of-scope`，返回域外声明 + 四入口
- **围栏是双向的**：域外判定高于关键词——"生成一份天气报告"命中规则词"报告"，
  但模型说 none，规则层不得捞回（测试锚定）
- **实弹验证**：DeepSeek 对"今天天气怎么样"返回 none/conf=1.0，
  域外出口真实生效
- **缺点**：none 判定依赖模型自觉（prompt 层约束而非硬闸）——但硬闸在出口处：
  即便模型把域外请求错归某意图，执行结果也只是成本数据场景，模型没有任何
  自由文本通道把"别的思考"送达用户（生成层双闸 + 分类层枚举，通道全封闭）
- **裁决**：做——把"别想别的"从一句 prompt 请求变成一个有测试锚定的协议字段
