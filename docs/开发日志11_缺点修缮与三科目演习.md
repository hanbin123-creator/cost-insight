## 一、缺点一 · 声明与实现受控重复 → 发现已内建 + 补回归测试

- **盘点发现**：B1 落地时已采用"fn 返回 dict + build() 运行期逐组对账"架构
  （`产出字段集与声明不符` 断言），缺点一的解决方案**早已在代码里**——
  声明与实现的重复无法静默分叉：要么一致，要么 build 当场炸并指名差哪个键
- **决策**：代码不动，补一条负向回归测试：构造"声明照写、实现偷偷少产一个键"的说谎组，
  断言 import 校验全绿的情况下 build() 依然爆炸
- **优点**：防线从"存在"升级为"被测试锚定"，后人删掉对账断言会立刻红测试
- **缺点**：无新增缺点；唯一的教训是**记录缺点前应先盘点现状**——
  这次差点为一个已解决的问题重复开发
- **裁决**：做（测试）；诚实记录"缺点一在被提出时其实已解决"

## 二、缺点二 · YAML 配置漂移 + 三层命名 → 结构校验前置 + --init-yaml 骨架

- **决策**：①Mapping.__init__ 先跑 `_validate_structure`：三节必须是"键: 值"映射、
  aliases 必须是含 pattern/replace 的列表、pattern 必须能编译正则——
  写歪了报"结构校验失败：scalars 节必须是…"的人话，而非 KeyError 天书；
  ②extract_placeholders.py 新增 `--init-yaml`：换模板时从模板 + 旧 YAML 生成骨架，
  同名键复用旧映射、别名规则自动预填、其余标 TODO，漂移从"不可见"变"可审计"
- **优点**：YAML 最高发的坑（缩进/冒号/类型写歪）在学校门口被拦下；
  骨架是活标本，运维改完 diff 即知动了什么；官方模板实测生成骨架 TODO=0（全复用）
- **缺点**：结构校验是手写枚举（不引 jsonschema 依赖，赛会环境少依赖更稳），
  只覆盖已知错误模式；--init-yaml 是又一个需要维护的命令
- **裁决**：做——YAML 是比赛现场最可能被手改的文件，值得最高规格防手抖

## 三、缺点三 · 转换最坏 6 分钟 → 四层重设计（最坏 2 分钟）

- **关键洞察**：旧方案只问"等多久"没问"等什么"。LibreOffice 无头模式常见病是
  **PDF 早转完、进程赖着不退**——旧方案把这种实际成功判成失败白等 180s，还重试。
  这是最大宗的冤案
- **决策（四层）**：①起飞前检查：soffice/docx 缺失秒级报错不重试；
  ②**文件守望者**：Popen 后轮询产物，大小连续两轮稳定即判定成功，
  taskkill /T 主动收尾进程树——转完即走；③硬超时 180s→60s
  （实测正常转换 5-15s，4 倍冗余）；④**死因分类**：stderr 命中瞬时签名
  （lock/profile/busy/占用）或超时才重试，确定性故障立即报错
- **优点**：最坏耗时 6 分钟 → 2 分钟（用户要求 3 分钟以内，达成）；
  冤案平反后多数"偶发故障"根本不再发生；超时卡死必强制收尾进程树，不留僵尸
- **缺点**：守望者逻辑比傻等复杂（"大小稳定"要两轮确认）；主动杀进程理论上可能
  杀掉差一口气写完的转换（两轮稳定确认对冲，残留风险极低）；错误签名表是枚举，
  表外新型死法按保守方向处理（立即报错，不瞎重试）
- **裁决**：做——时间缩短是副产品，"成功不再被判失败"才是主产品
- **测试**：4 项 Popen 假身测试（瞬时故障重试成功/两次卡死强制收尾/确定性不重试/
  守望者早期成功 <5s 不等 30s 超时），全部 2s 内跑完

## 四、缺点四 · 演习只覆盖改名 → 扩三科目（实测 19.9s）

- **决策**：fire_drill.py 重构为三科目，凡 --write 的科目独立备份/finally 恢复：
  - **科目一·改名**（情形 B 完整应急链）：11.5s，与日志10 一致
  - **科目二·删除键**：--check 识别"模板删除"→ 映射校验照常通过 →
    少一格的模板照常出报告（优雅降级实证：缺的只是模板里的一格）
  - **科目三·新增键**（情形 C 的拒绝链路）：新增"本季度能耗"→ --check 报"模板新增"
    → 注册表重建 102 键 → **第一级拒绝**：映射校验指名无映射启动即炸 →
    **第二级拒绝**：即便 YAML 乱填 `energy.quarter.current` 假字段，
    双层校验第②层报"代码未声明"——系统算不了的数进不了报告
- **优点**：漂移三形态全部实测背书；"情形 C 属人工开发"从纸面声明变成
  被验证过的两级拒绝链路；每科目独立安全绳，互不影响
- **缺点**：演习脚本从 160 行涨到 280 行；总耗时 9s→20s（仍远小于人工演练）；
  拒绝链路的断言依赖报错文案（文案与演习耦合，可接受——文案本身就是契约）
- **裁决**：做——演习的意义就是覆盖所有形态，只演一种等于没演完
- **演习抓到的真 bug（第 4 个）**：三科目产同名报告互相覆盖证据 →
  实产后按科目改名留证。演习又一次证明它不是仪式

## 五、缺点五 · --assign 人工步 → 降摩擦（安全闸保留）

- **决策**：--write/--init-yaml 拒绝落盘时输出**可复制的完整命令骨架**
  （含模板路径、已有 assign、每个待判别键的 `--assign 键=??`），
  人只需把 ?? 改成 scalar 或 text——人工步压缩到一次复制粘贴；
  L3 LLM 建议分类按原排期板块4 后做（机器提案、人类签字，主路径永不依赖 LLM）
- **优点**：摩擦降到地板，安全闸原样保留；零风险
- **缺点**：无实质缺点；命令骨架在路径含空格时已加引号处理
- **裁决**：做——要消灭的是摩擦，不是闸
